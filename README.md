# هویدا (HOVIDA)

**آنچه مهم است، روشن می‌شود.**
تحلیل هوشمند رزومه‌ها برای تصمیم‌های بهتر در منابع انسانی.

هویدا یک محصول SaaS فارسی‌محور برای تیم‌های جذب است: هر سازمان فضای کاری جداگانه دارد، برای هر «فرصت شغلی» معیارهای وزن‌دار و پرسش‌نامه اختصاصی می‌سازد، رزومه‌ها را بارگذاری می‌کند و فهرستی مرتب‌شده بر اساس **میزان تطابق** همراه با **شواهد مستقیم از متن رزومه** تحویل می‌گیرد. هوش مصنوعی فقط توصیف می‌کند؛ **تصمیم نهایی همیشه با انسان است.**

---

## امکانات

| بخش | توضیح |
| --- | --- |
| **فضای کاری سازمانی** | ثبت‌نام با ایمیل و رمز، جداسازی کامل داده‌ها بین سازمان‌ها، نقش‌های مالک / مدیر / عضو |
| **نسخه نمایشی** | دکمه «ورود به نسخه نمایشی» یک فضای کاری خصوصی با ۵ فرصت شغلی و ۳۰ کاندید ساختگی می‌سازد که پس از ۲۴ ساعت خودکار حذف می‌شود |
| **فرصت‌های شغلی** | ساخت سه‌مرحله‌ای: اطلاعات شغل ← معیارها و پرسش‌نامه (پیشنهاد هوش مصنوعی یا «الگوی آماده دپارتمان» با برچسب شفاف) ← بارگذاری اختیاری رزومه؛ وضعیت باز / متوقف / بسته |
| **تحلیل رزومه** | PDF، Word، تصویر اسکن‌شده، متن یا ZIP؛ تحلیل در پس‌زمینه با نوار پیشرفت سراسری؛ هم‌سنجی نهایی کاندیداها؛ «بازبینی دقیق» برای خواندن بند به بند فایل اصلی |
| **برچسب‌های تطابق** | تطابق بالا · نیازمند بررسی · تطابق پایین · اطلاعات ناکافی — همیشه با آیکن، رنگ و درصد |
| **پنل کاندید** | خلاصه، دلایل تطابق، نکات قابل بررسی (با نقل‌قول از رزومه)، سنجش معیار به معیار، تجربه، تماس، تاریخچه تحلیل و تصمیم (تأیید / نیاز به بررسی / رد با دلیل) |
| **رزومه‌ها** | صف «در انتظار تصمیم» و فهرست‌های تأیید / رد / نیاز به بررسی در کل فضای کاری با فیلتر فرصت، دپارتمان و بازه زمانی |
| **مقایسه** | تا ۴ کاندید یک فرصت، معیار به معیار با برجسته‌سازی بهترین مقدار و مهارت‌های مشترک |
| **بانک استعداد** | نگهداری کاندیداهای ارزشمند با دپارتمان، یادداشت و برچسب |
| **گزارش‌ها** | روند رزومه‌ها، توزیع تطابق، قیف تصمیم‌گیری، دپارتمان‌ها، مهارت‌های پرتکرار و خروجی اکسل |
| **پیام‌ها** | پیش‌نویس دعوت به مصاحبه، درخواست اطلاعات، بانک استعداد و اعلام نتیجه با امضای سازمان (ارسال خودکار ندارد) |
| **جست‌وجوی سراسری** | `Ctrl/⌘ + K`؛ حساس نبودن به «ی/ي»، «ک/ك»، نیم‌فاصله و ارقام فارسی |
| **اعلان‌ها و فعالیت تیم** | هر تصمیم با نام تصمیم‌گیرنده و زمان ثبت می‌شود |

## اصول محصول

- **شواهد، نه حدس:** هر امتیاز معیار با نقل‌قول مستقیم از رزومه همراه است؛ نبود شاهد صریحاً گفته می‌شود.
- **هوش مصنوعی مطمئن جلوه نمی‌کند:** برچسب «پیشنهاد هویدا»، سطح اطمینان و یادآوری «تصمیم نهایی با شماست».
- **صداقت در نبود هوش مصنوعی:** پیشنهاد معیار بدون AI شکست صادقانه دارد و کاربر می‌تواند «الگوی آماده» را انتخاب کند؛ تحلیل رزومه با موتور محلی کلیدواژه‌ای و برچسب «تحلیل محلی» ادامه پیدا می‌کند.
- **بی‌طرفی:** نام، جنسیت، سن، وضعیت تأهل و ملیت در امتیاز اثری ندارد؛ آواتارها حروف اول نام‌اند، بدون حدس جنسیت.
- **بدون عدد ساختگی:** «زمان صرفه‌جویی‌شده» همیشه با برچسب «برآورد» و فرض محاسبه نمایش داده می‌شود.

## اجرای محلی

```bash
npm install
cp .env.example .env          # اختیاری: کلید هوش مصنوعی را تنظیم کنید
npm run dev                   # http://localhost:3000
```

بدون هیچ کلیدی هم برنامه کامل کار می‌کند (نسخه نمایشی، الگوهای آماده، موتور محلی).

### ساخت و اجرای نسخه production

```bash
npm run build                 # Vite (کلاینت) + esbuild (سرور) → dist/
NODE_ENV=production npm start
```

## پیکربندی (متغیرهای محیطی)

| متغیر | توضیح |
| --- | --- |
| `PORT` | پورت سرور (پیش‌فرض ۳۰۰۰) |
| `DATA_DIR` | محل ذخیره داده و فایل‌ها (پیش‌فرض `./data`) |
| `APP_SECRET` | کلید امضای پیوندهای فایل؛ اگر خالی باشد خودکار ساخته و در `DATA_DIR` نگهداری می‌شود |
| `AI_PROVIDER` | `auto` (پیش‌فرض)، `gemini`، `openai` یا `off` |
| `GEMINI_API_KEY`، `GEMINI_MODEL` | Google Gemini |
| `OPENAI_API_KEY`، `OPENAI_BASE_URL`، `OPENAI_MODEL` | هر سرویس سازگار با OpenAI، از جمله درگاه‌های داخلی |
| `DISABLE_DEMO=1` | غیرفعال کردن نسخه نمایشی |
| `LEGACY_OWNER_EMAIL` | فقط ثبت‌نام با این ایمیل، داده‌های نسخه قدیمی را تحویل می‌گیرد |

در حالت `auto` اگر کلید Gemini موجود باشد از آن، وگرنه از سرویس سازگار با OpenAI استفاده می‌شود. کلیدها هرگز به مرورگر ارسال نمی‌شوند. سرویس OpenAI-compatible با JSON mode و ارسال تصویر/PDF کار می‌کند و اگر درگاهی از فایل یا JSON mode پشتیبانی نکند، خودکار با متن استخراج‌شده دوباره تلاش می‌کند.

## استقرار روی Render

فایل `render.yaml` آماده است (دیسک دائمی ۱ گیگابایت روی `data/`). کلیدهای هوش مصنوعی را در داشبورد Render تنظیم کنید.

> **مهاجرت از نسخه قدیمی:** فایل `data/screening-store.json` در اولین اجرا خودکار به ساختار جدید منتقل می‌شود (نشست‌ها ← فرصت‌های شغلی؛ رزومه‌های حذف‌شده واقعاً پاک می‌شوند). **اولین سازمانی که ثبت‌نام کند** این داده‌ها را تحویل می‌گیرد؛ برای اطمینان، پیش از استقرار `LEGACY_OWNER_EMAIL` را روی ایمیل مدیر منابع انسانی تنظیم کنید.

## امنیت

- رمزهای عبور با **scrypt** و نمک تصادفی؛ نشست‌ها توکن‌های تصادفی که فقط هش SHA-256 آن‌ها ذخیره می‌شود؛ تغییر رمز، نشست‌های دیگر را می‌بندد.
- جداسازی سازمان‌ها در تمام پرس‌وجوها؛ رکورد سازمان دیگر دقیقاً مثل رکورد ناموجود رفتار می‌کند.
- فایل‌ها فقط با **پیوند امضاشده HMAC و ده‌دقیقه‌ای** باز می‌شوند (توکن نشست هرگز در URL نمی‌آید).
- محدودیت نرخ برای ورود، ثبت‌نام و نسخه نمایشی؛ حذف واقعی رزومه و فایل اصلی.

## آزمون‌ها

```bash
npm run lint                  # tsc --noEmit
npm test                      # منطق خالص، قطع‌کننده مدار AI، مهلت و لغو درخواست‌ها
# با یک سرور در حال اجرا روی 3111:
DATA_DIR=/tmp/hv PORT=3111 NODE_ENV=production node dist/server.cjs &
npm run test:api              # آزمون سرتاسری API: احراز هویت، جداسازی سازمان‌ها، فایل‌ها، تحلیل
BASE=http://127.0.0.1:3111 npm run test:mount   # اجرای واقعی اپ در jsdom
```

## ساختار پروژه

```
server.ts                 راه‌انداز Express (API + Vite/فایل‌های استاتیک، خاموشی امن)
server/db.ts              ذخیره‌سازی چندمستاجری، مهاجرت نسخه قدیم، گزارش‌ها و جست‌وجو
server/auth.ts            scrypt، نشست‌ها، نقش‌ها، پیوند امضاشده، محدودیت نرخ
server/ai/provider.ts     Gemini و OpenAI-compatible، قطع‌کننده مدار، پیام‌های خطای فارسی
server/ai/screening.ts    پیشنهاد معیار، تحلیل رزومه، هم‌سنجی، پیش‌نویس پیام، موتور محلی، الگوها
server/demo-seed.ts       ساخت فضای کاری نمایشی
server/routes/*           مسیرهای API (auth، org، jobs، resumes، insights)
src/pages/*               صفحه‌ها (لندینگ، ورود، داشبورد، فرصت‌ها، رزومه‌ها، مقایسه، بانک، گزارش، تنظیمات)
src/components/ui/*       کیت طراحی هویدا
src/components/brand/*    لوگو و نشان (SVG)
src/lib/*                 مسیریاب، API، احراز هویت، اجرای تحلیل در پس‌زمینه، قالب‌بندی فارسی
public/brand/*            دارایی‌های برند (نشان، لوگوتایپ، آیکن اپ)
scripts/brand/            اسکریپت بازتولید لوگو از روی فونت‌ها
docs/DESIGN-SYSTEM.md     مستند سیستم طراحی
```

سیستم طراحی (رنگ‌ها، تایپوگرافی، اجزا و قواعد دسترس‌پذیری) در [`docs/DESIGN-SYSTEM.md`](docs/DESIGN-SYSTEM.md) مستند شده است.
