# هویدا (HOVIDA)

**آنچه مهم است، روشن می‌شود.**
تحلیل هوشمند رزومه‌ها برای تصمیم‌های بهتر در منابع انسانی.

هویدا یک محصول SaaS فارسی‌محور برای تیم‌های جذب است: هر سازمان فضای کاری جداگانه دارد، برای هر «فرصت شغلی» معیارهای وزن‌دار و پرسش‌نامه اختصاصی می‌سازد، رزومه‌ها را بارگذاری می‌کند و فهرستی مرتب‌شده بر اساس **میزان تطابق** همراه با **شواهد مستقیم از متن رزومه** تحویل می‌گیرد. هوش مصنوعی فقط توصیف می‌کند؛ **تصمیم نهایی همیشه با انسان است.**

## امکانات

| بخش | توضیح |
| --- | --- |
| **فضای کاری سازمانی** | ثبت‌نام با ایمیل و رمز، جداسازی کامل داده‌ها بین سازمان‌ها، نقش‌های مالک / مدیر / عضو |
| **نسخه نمایشی** | دکمه «ورود به نسخه نمایشی» یک فضای کاری خصوصی با ۵ فرصت شغلی و حدود ۳۰ کاندید ساختگی (شامل یک رزومهٔ تکراری برای نمایش برچسب) می‌سازد که پس از ۲۴ ساعت خودکار حذف می‌شود |
| **فرصت‌های شغلی** | ساخت سه‌مرحله‌ای: اطلاعات شغل ← معیارها و پرسش‌نامه (پیشنهاد هوش مصنوعی یا «الگوی آماده دپارتمان» با برچسب شفاف) ← بارگذاری اختیاری رزومه؛ وضعیت باز / متوقف / بسته |
| **تحلیل رزومه — هر قالبی** | PDF (متنی و اسکن‌شده)، Word (DOCX با سربرگ و کادرهای متن، DOC)، ODT، RTF، عکس و اسکن (JPG، PNG، HEIC، TIFF چندصفحه‌ای، BMP، GIF، WebP، AVIF، SVG)، اکسل و CSV، پاورپوینت، صفحه وب و MHTML، ایمیل (EML و MSG همراه پیوست‌ها)، EPUB، XPS، JSON و XML، ZIP/TAR/GZ و رزومه صوتی/ویدیویی؛ تشخیص قالب از محتوای فایل (نه پسوند)، کنار گذاشتن متن درهم و خواندن مستقیم فایل با هوش مصنوعی؛ هم‌سنجی نهایی و «بازبینی دقیق» |
| **پنل مدیریت سامانه** (`/admin`) | نمای کلی، فضاهای کاری (تعلیق، تمدید نسخه نمایشی، ورود پشتیبانی، حذف)، کاربران (نقش، مدیر سامانه، غیرفعال‌سازی، بازنشانی رمز، بستن نشست‌ها)، تنظیمات سامانه (ثبت‌نام، نسخه نمایشی، محدودیت حجم و تعداد، اطلاعیه سراسری، حالت نگهداری) و گزارش رویدادها |
| **پشتیبان‌گیری و انتقال** | یک فایل ZIP کامل (همه فضاهای کاری، کاربران، رزومه‌ها همراه فایل اصلی، تصمیم‌ها و تنظیمات) با یک کلیک؛ بازیابی روی همان سرور یا سرور دیگر با بارگذاری تکه‌تکه، بررسی محتوا پیش از تأیید و نوار پیشرفت — مثلاً برای انتقال از Render به Cloudflare |
| **کلیدهای هوش مصنوعی** | تا ۵ کلید Gemini (با آدرس پراکسی اختیاری) یا سازگار با OpenAI، رمزنگاری‌شده؛ جابه‌جایی خودکار و بی‌وقفه هنگام محدودیت نرخ، اتمام سهمیه، کلید نامعتبر یا قطعی؛ راهبرد اولویت‌دار یا چرخشی؛ سقف درخواست در دقیقه/روز؛ آزمایش و وضعیت زنده هر کلید |
| **رفتار هوش مصنوعی** | دستورالعمل‌های نسخه‌دار و قابل ویرایش (اصول، امتیازدهی، خواندن انواع سند، انصاف، سطح نقش، بازبینی دقیق، لحن خروجی، دستور اختصاصی)، سه سطح سخت‌گیری، ۲۷ راهنمای تخصصی صنعت با تشخیص خودکار، آزمایشگاه و تاریخچه نسخه‌ها |
| **برچسب‌های تطابق** | تطابق بالا · نیازمند بررسی · تطابق پایین · اطلاعات ناکافی — همیشه با آیکن، رنگ و درصد |
| **تشخیص رزومهٔ تکراری** | هر رزومه در غربالگری هر دپارتمان با سابقهٔ همان دپارتمان در همان فضای کاری مقایسه می‌شود و برچسب «جدید» یا «تکراری» می‌گیرد؛ تطابق بر پایهٔ هش فایل، متن نرمال‌شدهٔ رزومه، ایمیل یا شمارهٔ تماس (نه نام و نام فایل). رزومهٔ تکراری به رکورد قبلی و فرصت شغلی آن پیوند دارد، فیلتر «فقط تازه‌ها / فقط تکراری‌ها» دارد و در خروجی اکسل هم مشخص است. رزومه‌ای که هیچ نشانهٔ قابل تطبیقی ندارد «نامشخص» می‌ماند تا اشتباهاً تازه شمرده نشود. |
| **پنل کاندید** | خلاصه، دلایل تطابق، نکات قابل بررسی (با نقل‌قول از رزومه)، سنجش معیار به معیار، تجربه، تماس، تاریخچه تحلیل و تصمیم (تأیید / نیاز به بررسی / رد با دلیل) |
| **رزومه‌ها** | صف «در انتظار تصمیم» و فهرست‌های تأیید / رد / نیاز به بررسی در کل فضای کاری با فیلتر فرصت، دپارتمان و بازه زمانی |
| **جست‌وجوی استعداد (LinkedIn)** | انتخاب دپارتمان و نوشتن «دنبال چه متخصصی با چه شرایطی هستم»؛ ساخت کوئری جست‌وجو با هوش مصنوعی (و کوئری بولی قابل ویرایش/کپی)، جست‌وجو در سرویس رسمی/دارای مجوز لینکدین سازمان با تمرکز روی افراد Open to work، نمایش پروفایل (عنوان، شهر، «کجاها بوده»، مهارت‌ها، لینک پروفایل) و افزودن هر پروفایل به فرصت شغلی به‌عنوان کاندیدای قابل غربالگری. بدون اتصال، صادقانه «تنظیم نشده» می‌گوید و هیچ پروفایلی از خودش نمی‌سازد. |
| **ایمیل سازمان** | اتصال SMTP هر فضای کاری (Gmail/Workspace، Outlook، Zoho، سرور داخلی) با رمز رمزنگاری‌شده؛ ویرایش پیش‌نویس و ارسال واقعی از داخل سایت، ثبت در تاریخچه با نام فرستنده و علامت «ارسال‌شده» روی کاندیدا |
| **Google Calendar** | اتصال حساب گوگل هر فضای کاری با OAuth؛ تعیین جلسهٔ مصاحبه (عنوان، تاریخ شمسی، ساعت تهران، مدت، مصاحبه‌گران، مکان/Google Meet، توضیح) و ثبت رویداد در تقویم با ارسال دعوت‌نامه به کارجو؛ لغو جلسه رویداد گوگل را هم حذف می‌کند. بدون اتصال: جلسه در هویدا ذخیره و فایل ICS قابل دریافت است |
| **مقایسه** | تا ۴ کاندید یک فرصت، معیار به معیار با برجسته‌سازی بهترین مقدار و مهارت‌های مشترک |
| **بانک استعداد** | نگهداری کاندیداهای ارزشمند با دپارتمان، یادداشت و برچسب |
| **گزارش‌ها** | روند رزومه‌ها، توزیع تطابق، قیف تصمیم‌گیری، دپارتمان‌ها، مهارت‌های پرتکرار و خروجی اکسل |
| **پیام‌ها** | پیش‌نویس دعوت به مصاحبه، درخواست اطلاعات، بانک استعداد و اعلام نتیجه با امضای سازمان (ارسال خودکار ندارد) |
| **جست‌وجوی سراسری** | `Ctrl/⌘ + K`؛ حساس نبودن به «ی/ي»، «ک/ك»، نیم‌فاصله و ارقام فارسی |
| **اعلان‌ها و فعالیت تیم** | هر تصمیم با نام تصمیم‌گیرنده و زمان ثبت می‌شود |

## اصول محصول

- **شواهد، نه حدس:** هر امتیاز معیار با نقل‌قول مستقیم از رزومه همراه است؛ نبود شاهد صریحاً گفته می‌شود.
- **هوش مصنوعی مطمئن جلوه نمی‌کند:** برچسب «پیشنهاد هویدا»، سطح اطمینان و یادآوری «تصمیم نهایی با شماست».
- **صداقت در نبود هوش مصنوعی:** پیشنهاد معیار بدون AI شکست صادقانه دارد و کاربر می‌تواند «الگوی آماده» را انتخاب کند؛ تحلیل رزومه با موتور محلی کلیدواژه‌ای و برچسب «تحلیل محلی» ادامه پیدا می‌کند.
- **بی‌طرفی:** نام، جنسیت، سن، وضعیت تأهل و ملیت در امتیاز اثری ندارد؛ آواتارها حروف اول نام‌اند، بدون حدس جنسیت.
- **بدون عدد ساختگی:** «زمان صرفه‌جویی‌شده» همیشه با برچسب «برآورد» و فرض محاسبه نمایش داده می‌شود.

## اجرای محلی

```bash
npm install
cp .env.example .env          # اختیاری: کلید هوش مصنوعی را تنظیم کنید
npm run dev                   # http://localhost:3000
```

بدون هیچ کلیدی هم برنامه کامل کار می‌کند (نسخه نمایشی، الگوهای آماده، موتور محلی).

### ساخت و اجرای نسخه production

```bash
npm run build                 # Vite (کلاینت) + esbuild (سرور) → dist/
NODE_ENV=production npm start
```

## اتصال‌ها (اختیاری، همه از داخل سایت)

بدون این اتصال‌ها هم بقیهٔ هویدا کامل کار می‌کند؛ هر کدام که تنظیم نشده باشد، صادقانه «تنظیم نشده» نشان می‌دهد و موفقیت جعلی نمی‌سازد.

| اتصال | کجا وارد می‌شود | سطح |
| --- | --- | --- |
| کلید هوش مصنوعی | `/admin` › **کلیدهای هوش مصنوعی** | یک‌بار برای کل نصب |
| سرویس جست‌وجوی LinkedIn (آدرس + توکن، یا Actor آمادهٔ Apify) | `/admin` › **کلیدها و اتصال‌ها** | یک‌بار برای کل نصب |
| Google OAuth Client (Client ID/Secret) | `/admin` › **کلیدها و اتصال‌ها** | یک‌بار برای کل نصب |
| صندوق ایمیل مشترک سامانه (SMTP) | `/admin` › **کلیدها و اتصال‌ها** | یک‌بار برای کل نصب (جایگزین فضاهای کاری بدون صندوق) |
| خط پیامک مشترک سامانه (کاوه‌نگار / sms.ir) | `/admin` › **کلیدها و اتصال‌ها** | یک‌بار برای کل نصب (جایگزین فضاهای کاری بدون خط) |
| صندوق ایمیل سازمان (SMTP) | تنظیمات › **اتصال‌ها** › ایمیل سازمان | برای هر فضای کاری (اولویت بر صندوق مشترک) |
| پیامک سازمان | تنظیمات › **اتصال‌ها** › پیامک سازمان | برای هر فضای کاری (اولویت بر خط مشترک) |
| اتصال حساب گوگل، وب‌هوک چت، SSO | تنظیمات › **اتصال‌ها** | برای هر فضای کاری |

صفحهٔ «پنل مدیریت ← کلیدها و اتصال‌ها» یک **نقشهٔ کلیدها** نشان می‌دهد: برای هر کلید، وضعیت (ثبت‌شده / تنظیم‌نشده)،
اینکه چه بخشی از محصول را روشن می‌کند و دکمهٔ رفتن به همان بخش. رمزها رمزنگاری‌شده ذخیره می‌شوند و پیش از ذخیره آزمایش
می‌شوند؛ ترتیب انتخاب هنگام ارسال **حساب اختصاصی فضای کاری ← حساب مشترک سامانه ← متغیرهای محیطی ← تنظیم‌نشده** است و
در تنظیمات هر فضای کاری نوشته می‌شود که نامه از کدام حساب می‌رود. جزئیات: [`docs/CREDENTIALS-HUB.md`](docs/CREDENTIALS-HUB.md).

- **جست‌وجوی استعداد / LinkedIn:** دسترسی رسمی سازمان لازم است (Talent Solutions یا سرویس دادهٔ دارای مجوز). راهنما و
  قرارداد API: [`docs/CONNECT-LINKEDIN.md`](docs/CONNECT-LINKEDIN.md).
- **ایمیل سازمان (SMTP):** راهنما: [`docs/CONNECT-EMAIL.md`](docs/CONNECT-EMAIL.md).
- **همهٔ کلیدها یک‌جا:** نقشهٔ کلیدها، ترتیب اولویت و قاعدهٔ «تنظیم نشده»: [`docs/CREDENTIALS-HUB.md`](docs/CREDENTIALS-HUB.md).
- **دیده‌شدن آگهی در گوگل:** نشانه‌گذاری `JobPosting`، مهلت درخواست، نقشهٔ سایت و جمع‌کننده‌های ایرانی: [`docs/JOB-POSTING.md`](docs/JOB-POSTING.md).
- **معرفی همکار:** لینک اختصاصی هر عضو، ثبت خودکار معرفی در قیف، پاداش با دو تأیید انسانی و شرط دورهٔ آزمایشی: [`docs/REFERRALS.md`](docs/REFERRALS.md).
- **دسترسی به هر آگهی:** استخدام محرمانه را به افراد مشخص محدود کنید؛ قفل روی فهرست، تخته، کارجو، فایل، پیشنهاد و جست‌وجو اعمال می‌شود: [`docs/JOB-ACCESS.md`](docs/JOB-ACCESS.md).
- **پورتال دوزبانه:** فارسی و انگلیسی، نسخهٔ انگلیسی هر آگهی به قلم و تأیید منابع انسانی، `hreflang` و `JobPosting.inLanguage`: [`docs/PORTAL-LANGUAGES.md`](docs/PORTAL-LANGUAGES.md).
- **برابری فرصت‌ها:** پرسش‌های داوطلبانه و بی‌نام، پنهان از تصمیم‌گیرنده و گزارش تجمیعی با پنهان‌سازی گروه‌های کوچک: [`docs/EEO.md`](docs/EEO.md).
- **مصاحبهٔ ویدئویی:** چند پرسش کوتاه، ضبط با گوشی کارجو بدون نصب چیزی، سقف تعداد ضبط، پخش خصوصی با لینک امضاشده و امتیاز انسانی (بدون ارزیابی چهره): [`docs/VIDEO-INTERVIEWS.md`](docs/VIDEO-INTERVIEWS.md).
- **نصب روی دستگاه:** وب‌اپ نصب‌شدنی با آیکن، تمام‌صفحه، میان‌برها و صفحهٔ آفلاین فارسی — بدون کش‌کردن دادهٔ کارجویان: [`docs/INSTALL-APP.md`](docs/INSTALL-APP.md).
- **تحویل پس از استخدام:** برنامه‌ای که با پذیرش پیشنهاد خودکار ساخته می‌شود — روز شروع شمسی، مسئول، چک‌لیست با نام و زمان هر تیک، پیام خوش‌آمد از صندوق خودتان و خروجی CSV برای حقوق و دستمزد: [`docs/ONBOARDING.md`](docs/ONBOARDING.md).
- **اتاق مصاحبهٔ زنده:** یک لینک برای هر جلسه، تماس مستقیم دو مرورگر (WebRTC) با اشتراک صفحه و چتِ کنارِ تماسِ بی‌ذخیره، بدون نصب و بدون ضبط — سرور فقط پیام آدرس‌دهی را رد می‌کند؛ و اگر شبکهٔ شرکتی اتصال مستقیم را ببندد، **رلهٔ TURN خودِ سازمان** از «تنظیمات ← اتصال‌ها» با گذرواژهٔ موقت وصل می‌شود و صفحه صادقانه می‌گوید رله هست یا نه: [`docs/INTERVIEW-ROOM.md`](docs/INTERVIEW-ROOM.md).
- **انتقال به حقوق و دستمزد:** فهرست استخدام‌شدگان از برنامهٔ تحویل، کد پرسنلی، CSV با BOM برای اکسل، ستون‌های قابل‌تغییر، و ارسال امضاشدهٔ JSON به سیستم حقوق — با خالی‌ماندن هر چیزی که نمی‌دانیم: [`docs/PAYROLL-HRIS.md`](docs/PAYROLL-HRIS.md).
- **ریشهٔ هر قابلیت:** جدولی که برای هر فیچر می‌گوید چه می‌کند، از کدام رقیب الهام گرفته و کدام بخشش بازسازی پروتکل (نه کپی کد) بوده: [`docs/FEATURE-ORIGIN.md`](docs/FEATURE-ORIGIN.md).
- **انتشار در جاب‌بورد:** متن آمادهٔ هر آگهی برای جابینجا/جاب‌ویژن/ای‌استخدام/کوئرا/ایران‌تلنت با لینک درخواست خودتان، و ثبت این‌که چه روزی و کجا منتشر شد — بدون ادعای انتشار خودکار، چون این بوردها رابط نوشتن عمومی ندارند: [`docs/JOB-POSTING.md`](docs/JOB-POSTING.md).
- **کارتابل تأیید:** یک صفحه که می‌گوید «منتظر من چه چیزی است» — مرحلهٔ پیشنهاد شغلی، پیش‌نویس اتوماسیون و پاداش معرفی، با نوبت هر نفر؛ تصمیم‌هایی که این‌جا گرفته می‌شوند هیچ پیامی به کارجو نمی‌فرستند و تأیید نامه همیشه در صفحه‌ای است که متن نامه را نشان می‌دهد: [`docs/APPROVAL-INBOX.md`](docs/APPROVAL-INBOX.md).

## پیکربندی (متغیرهای محیطی)

| متغیر | توضیح |
| --- | --- |
| `PORT` | پورت سرور (پیش‌فرض ۳۰۰۰) |
| `DATA_DIR` | محل ذخیره داده و فایل‌ها (پیش‌فرض `./data`) |
| `STORAGE_DRIVER` | `fs` (پیش‌فرض، دیسک `DATA_DIR`) یا `remote` (ذخیره‌ساز راه دور؛ روی Cloudflare خودکار تنظیم می‌شود و داده‌ها در R2 می‌مانند) |
| `STORAGE_URL`، `STORAGE_TOKEN` | نشانی ذخیره‌ساز راه دور و توکن اختیاری آن (فقط با `STORAGE_DRIVER=remote`) |
| `APP_SECRET` | کلید امضای پیوندهای فایل و رمزنگاری کلیدهای هوش مصنوعی؛ اگر خالی باشد خودکار ساخته و کنار داده‌ها (`DATA_DIR` یا R2) نگهداری می‌شود. **ثابت نگهش دارید** (تغییرش کلیدهای ثبت‌شده را ناخوانا می‌کند؛ هنگام انتقال سرور همان مقدار قبلی را بگذارید) |
| `ADMIN_EMAILS` | ایمیل(های) مدیران سامانه، جدا با ویرگول؛ این حساب‌ها به `/admin` دسترسی دارند |
| `AI_PROVIDER` | `auto` (پیش‌فرض)، `gemini`، `openai` یا `off` (خاموشی کامل، حتی کلیدهای پنل مدیریت) |
| `GEMINI_API_KEY`، `GEMINI_MODEL` | (اختیاری) کلید Gemini روی سرور؛ پشتیبانِ کلیدهای پنل مدیریت |
| `OPENAI_API_KEY`، `OPENAI_BASE_URL`، `OPENAI_MODEL` | (اختیاری) هر سرویس سازگار با OpenAI، از جمله درگاه‌های داخلی |
| `DISABLE_DEMO=1` | غیرفعال کردن نسخه نمایشی |
| `LEGACY_OWNER_EMAIL` | ایمیل حسابی که داده‌های نسخه قدیمی (تک‌سازمانی) را تحویل می‌گیرد؛ بدون آن، این داده‌ها به هیچ‌کس نشان داده نمی‌شوند |
| `CLIENT_IP_HEADER` | سرآیندی که لبه شبکه با IP واقعی کاربر پر می‌کند (پشت Cloudflare: `cf-connecting-ip`)؛ روی Render خودکار همین است |
| `TRUST_PROXY_HOPS` | اگر سرآیند بالا نباشد: تعداد پراکسی‌های جلوی سرور برای خواندن `X-Forwarded-For` از راست (پیش‌فرض ۱؛ بدون پراکسی ۰) |

روش پیشنهادی: کلیدها را در **پنل مدیریت › کلیدهای هوش مصنوعی** ثبت کنید (تا ۵ کلید با جابه‌جایی خودکار). کلیدهای متغیرهای محیطی همچنان کار می‌کنند و بعد از کلیدهای پنل استفاده می‌شوند. کلیدها هرگز به مرورگر ارسال نمی‌شوند. سرویس OpenAI-compatible با JSON mode و ارسال تصویر/PDF کار می‌کند و اگر درگاهی از فایل یا JSON mode پشتیبانی نکند، خودکار با متن استخراج‌شده دوباره تلاش می‌کند.

## پنل مدیریت سامانه (`/admin`)

اولین مدیر سامانه به یکی از این دو روش تعیین می‌شود:

1. **متغیر `ADMIN_EMAILS`:** ایمیل خود را تنظیم کنید و **بلافاصله** با همان ایمیل ثبت‌نام کنید (حتی وقتی ثبت‌نام عمومی بسته است، این ایمیل‌ها اجازه دارند)؛ `/admin` باز می‌شود. ایمیل‌ها تأیید نمی‌شوند، پس تا وقتی با آن ایمیل حسابی ساخته نشده، سرور در لاگ هشدار می‌دهد و کد راه‌اندازی را هم چاپ می‌کند. مدیر یک فضای کاری نمی‌تواند با این ایمیل‌ها عضو بسازد.
2. **کد راه‌اندازی یک‌بارمصرف:** تا وقتی هیچ مدیری وجود ندارد، سرور هنگام شروع کدی مثل `HV-XXXX-XXXX-XXXX` در لاگ چاپ می‌کند؛ وارد حساب خود شوید، به `/admin` بروید و کد را وارد کنید.

پس از آن، مدیران دیگر را از بخش «کاربران» تعیین کنید. همه تغییرات پنل در «گزارش رویدادها» با نام انجام‌دهنده ثبت می‌شود؛ «ورود پشتیبانی» یک نشست دوساعته و برچسب‌دار در زبانه جداگانه باز می‌کند (حتی برای فضای کاری تعلیق‌شده)، به خود پنل دسترسی ندارد و هر کاری در آن با نام «پشتیبانی هویدا» در فعالیت‌های همان فضای کاری ثبت می‌شود.

## استقرار روی Cloudflare (پیشنهادی)

هویدا کامل روی Cloudflare اجرا می‌شود: صفحه‌ها از لبه شبکه Cloudflare (Workers)، سرور Node در **Cloudflare Containers** و داده‌ها و فایل‌های رزومه در **R2**. پیکربندی آماده است (`wrangler.jsonc`، `Dockerfile`، `cloudflare/`). راهنمای گام‌به‌گام فارسی — دامنه، تنظیمات، اتصال GitHub، انتقال داده‌ها از Render و هزینه برآوردی — در [`docs/DEPLOY-CLOUDFLARE.md`](docs/DEPLOY-CLOUDFLARE.md) است.

> آدرس‌های `*.workers.dev` در ایران فیلتر هستند؛ برای کاربران داخل ایران دامنه اختصاصی را به Worker وصل کنید.

## استقرار روی Render

فایل `render.yaml` آماده است (دیسک دائمی ۱ گیگابایت روی `data/`). پس از استقرار، `ADMIN_EMAILS` را تنظیم کنید (یا کد راه‌اندازی را از لاگ بردارید) و کلیدهای هوش مصنوعی را در پنل مدیریت ثبت کنید.

> **مهاجرت از نسخه قدیمی:** فایل `data/screening-store.json` در اولین اجرا خودکار به ساختار جدید منتقل می‌شود (نشست‌ها ← فرصت‌های شغلی؛ رزومه‌های حذف‌شده واقعاً پاک می‌شوند). این داده‌ها اطلاعات شخصی کاندیداها هستند، پس **فقط** به حسابی داده می‌شوند که ایمیلش در `LEGACY_OWNER_EMAIL` آمده است — چه همان ایمیل بعداً ثبت‌نام کند، چه از قبل حساب داشته باشد (کافی است متغیر را تنظیم و سرویس را یک بار دوباره راه‌اندازی کنید). تا آن زمان داده‌ها پنهان می‌مانند و سرور در لاگ راهنمایی می‌کند.

## امنیت

- رمزهای عبور با **scrypt** و نمک تصادفی؛ نشست‌ها توکن‌های تصادفی که فقط هش SHA-256 آن‌ها ذخیره می‌شود؛ تغییر رمز، نشست‌های دیگر را می‌بندد.
- جداسازی سازمان‌ها در تمام پرس‌وجوها؛ رکورد سازمان دیگر دقیقاً مثل رکورد ناموجود رفتار می‌کند.
- فایل‌ها فقط با **پیوند امضاشده HMAC و ده‌دقیقه‌ای** باز می‌شوند (توکن نشست هرگز در URL نمی‌آید).
- محدودیت نرخ برای ورود، ثبت‌نام و نسخه نمایشی؛ حذف واقعی رزومه و فایل اصلی.
- کلیدهای هوش مصنوعی با AES-256-GCM (کلید مشتق از `APP_SECRET`) ذخیره می‌شوند و API فقط بخش کوتاهی از آن‌ها را نشان می‌دهد.
- فایل‌های بارگذاری‌شده (HTML، SVG و…) هرگز در دامنه برنامه اجرا نمی‌شوند: فقط PDF، تصویر و متن ساده قابل پیش‌نمایش‌اند و بقیه به‌صورت دانلود با `Content-Security-Policy: sandbox` ارسال می‌شوند.

```bash
npm run test:api              # آزمون سرتاسری API: احراز هویت، جداسازی سازمان‌ها، فایل‌ها، تحلیل
BASE=http://127.0.0.1:3111 npm run test:mount   # اجرای واقعی اپ در jsdom
```

### نمایش محلی اتصال‌ها بدون سرویس واقعی

```bash
node scripts/mock-linkedin.mjs --port 9911 &   # سرویس جست‌وجوی ساختگی (افراد داستانی)
node scripts/mock-apify.mjs --port 9922 &     # پلتفرم Apify ساختگی (Actor جست‌وجوی پروفایل)
node scripts/mock-smtp.mjs --port 2525 &       # صندوق SMTP آزمایشی: پیام‌ها فقط چاپ می‌شوند
LINKEDIN_API_URL=http://127.0.0.1:9911/search LINKEDIN_ACCESS_TOKEN=demo npm run dev
```

سرویس جست‌وجو را در `/admin` › «اتصال‌ها» با آدرس `http://127.0.0.1:9911/search` و توکن `demo` ثبت کنید (یا همان دو
متغیر محیطی بالا را بگذارید)، و صندوق ایمیل را در «تنظیمات ← اتصال‌ها» با سرور `127.0.0.1`، پورت `2525`، اتصال امن خاموش.
هیچ ایمیل واقعی ارسال نمی‌شود و هیچ دادهٔ واقعی لینکدین خوانده نمی‌شود.
