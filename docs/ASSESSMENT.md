# آزمون و ارزیابی

> **چکیده:** کارجوی مناسب را نمی‌شود فقط از رزومه شناخت. هویدا **پنج آزمون آماده** دارد:
> سه آزمون قضاوت موقعیتی و نمونه‌کار با **کلید امتیاز روشن**، و یک آزمون **رفتار کاری**
> با پنج بُعد. لینک آزمون از پروندهٔ کارجو ساخته می‌شود، با صندوق سازمان فرستاده می‌شود،
> کارجو آن را در یک صفحهٔ عمومی و بدون حساب پاسخ می‌دهد، و نتیجه در همان پرونده می‌نشیند.
>
> **همان اول، صادقانه:** این‌ها آزمون روان‌سنجیِ هنجارشده نیستند. نه گروه هنجار دارند،
> نه ادعای IQ یا برچسب شخصیت. آن‌ها **نمونه‌کار و قضاوت موقعیتی ساخت‌یافته‌اند** — همان
> چیزی که یک مصاحبه‌گر خوب در جلسه انجام می‌دهد، فقط یک‌دست و قابل مقایسه. برای آزمون
> هنجارشده (سنجمان، هایرکمپ و مانند آن) مسیر اتصال آماده است و در §۷ آمده.

مسیر در برنامه: **پروندهٔ کارجو ← اطلاعات بیشتر ← «آزمون و ارزیابی»**.
مسیر پاسخ برای کارجو: **`/assess/<token>`** — بدون حساب و بدون نصب.

## ۱. بانک آزمون‌ها

| آزمون | نوع | پرسش | زمان | چه چیزی می‌سنجد |
| --- | --- | --- | --- | --- |
| قضاوت موقعیتی: کارشناس جذب | قضاوت موقعیتی (کلید) | ۸ | ۱۲ دقیقه | صف رزومه، مدیر دیرپاسخ، پیشنهاد رقیب، بازخورد به کارجوی ردشده |
| قضاوت موقعیتی: فروش و مذاکره | قضاوت موقعیتی (کلید) | ۸ | ۱۲ دقیقه | اعتراض قیمت، تصمیم‌گیرندهٔ غایب، پیش‌بینی صادقانه، قول ندادن |
| نمونه‌کار: پشتیبانی مشتری | نمونه‌کار (کلید) | ۶ | ۸ دقیقه | تیکت مبهم، مشتری عصبانی، ارجاع، اولویت‌بندی، پیگیری |
| رفتار کاری (پنج بُعد) | مقیاس پنج‌درجه‌ای | ۱۵ | ۶ دقیقه | مسئولیت‌پذیری، همکاری، یادگیری، کار زیر فشار، ارتباط (۴ گزارهٔ معکوس) |
| قضاوت موقعیتی: رهبری تیم | قضاوت موقعیتی (کلید) | ۸ | ۱۲ دقیقه | بازخورد ضعیف، تعارض، بودجهٔ استخدام، فشار از بالا |

جمع: **۵ آزمون، ۴۵ پرسش**. برای هر نقش، برنامه یک آزمون پیشنهادی نشان می‌دهد
(فروش ← فروش، مدیر ← رهبری، جذب ← جذب، بقیه ← رفتار کاری) — پیشنهاد است، نه اجبار.

## ۲. جریان کار (چهار قدم)

```
۱) انتخاب آزمون        پروندهٔ کارجو ← «آزمون و ارزیابی» ← انتخاب از بانک
۲) ساخت لینک           «ساخت لینک آزمون»  →  هیچ ایمیلی نمی‌رود
۳) ارسال               کپی لینک، یا «ارسال با ایمیل سازمان» (از صندوق خود مشتری)
۴) پاسخ                کارجو در /assess/<token> بدون حساب پاسخ می‌دهد (یک‌بار)
۵) نتیجه               نمره/نمایه در همان پرونده، در فهرست آزمون‌های کارجو
```

نکته‌های عملی:

- **ساخت ≠ ارسال.** لینک اول ساخته می‌شود و در کادر نشان داده می‌شود؛ ایمیل فقط با
  کلیک روی دکمهٔ ارسال می‌رود. اگر صندوق سازمان وصل نباشد، پیام صریح
  «ایمیل سازمان وصل نیست؛ لینک را کپی کنید» می‌آید، نه ادای ارسال.
- **مهلت ۱۴ روز.** لینک منقضی می‌شود و در فهرست «منقضی» می‌ماند؛ حذف نمی‌شود تا شمارش
  صادق بماند. لینک تازه، آزمون تازه است.
- **یک لینک، یک پاسخ.** بعد از ثبت، همان لینک صفحهٔ تشکر نشان می‌دهد، نه فرم.
- **همهٔ سؤال‌ها الزامی‌اند.** پاسخ ناقص ثبت نمی‌شود (سرور هم رد می‌کند، نه فقط دکمه).
- **وضعیت‌ها:** فرستاده‌شده ← در حال پاسخ (اولین باز شدن) ← تکمیل‌شده. لغو هم ممکن است
  تا وقتی تکمیل نشده؛ آزمون تکمیل‌شده لغو نمی‌شود چون نتیجه در پرونده می‌ماند.

## ۳. امتیازدهی — دقیقاً چه اتفاقی می‌افتد

### آزمون‌های کلیددار (قضاوت موقعیتی و نمونه‌کار)

هر گزینه یک امتیاز ۰ تا ۱۰ دارد. برای هر پرسش، امتیاز گزینهٔ انتخاب‌شده جمع می‌شود:

```
نمره = ۱۰۰ × (مجموع امتیاز گزینه‌ها) ÷ (۱۰ × تعداد پرسش‌ها)
```

| نمره | خوانش |
| --- | --- |
| ۷۵ تا ۱۰۰ | هم‌راستا با نقش |
| ۵۵ تا ۷۴ | نیازمند بررسی |
| ۰ تا ۵۴ | فاصلهٔ روشن با نقش |

کلید **هرگز** به مرورگر کارجو نمی‌رود: صفحهٔ عمومی فقط متن پرسش و برچسب گزینه‌ها را
می‌گیرد. حتی پیش‌نمایش مدیر هم امتیاز گزینه‌ها را نشان نمی‌دهد، فقط «چطور خوانده می‌شود».

### آزمون رفتار کاری

هر گزاره روی مقیاس ۱ تا ۵ (کاملاً مخالفم … کاملاً موافقم) پاسخ داده می‌شود. چهار گزاره
**معکوس** هستند (مثلاً «کارهای نیمه‌تمام زیادی دارم…»): موافقت با آن‌ها امتیاز منفی می‌گیرد
(`۶ − پاسخ`). برای هر بُعد:

```
امتیاز بُعد = ۱۰۰ × (میانگین پاسخ‌های بُعد − ۱) ÷ ۴
```

نتیجه **نمایهٔ پنج‌بُعدی** است، بی نمرهٔ کلی و بی برچسب شخصیت. در خود صفحه نوشته شده:
بُعد پایین، موضوع گفت‌وگو در مصاحبه است، نه دلیل رد.

## ۴. دسترسی و قواعد

| قاعده | چرا |
| --- | --- |
| دیدن و ساختن آزمون با هر عضو تیم | مصاحبه‌گر باید نتیجه را قبل از دور بعد ببیند؛ کار اوست |
| ارسال ایمیل با هر عضو، از صندوق سازمان | همان قاعدهٔ بقیهٔ پیام‌ها؛ تاریخچه نام فرستنده را دارد |
| غربالگری بی‌طرف = ۴۰۹ تا آشکارسازی | آزمون هم «تماس با کارجو» است؛ تا هویت آشکار نشود ساخته نمی‌شود |
| فضای کاری دیگر → ۴۰۴ | آزمون، دادهٔ همان سازمان است |
| پاسخ‌ها فقط روی سرور | کارفرما نتیجه را می‌بیند، نه کلیک‌ها را؛ کارجو هم نمره را نمی‌بیند |
| صفحهٔ عمومی بدون شناسه، بدون ایمیل، بدون امتیاز | هرچه در JSON نباشد، در ابزار توسعه‌دهنده هم نیست |
| محدودیت نرخ روی ثبت پاسخ | فرم عمومی نباید منبع محاسبهٔ رایگان شود |
| نگه‌داری داده | با ناشناس‌سازی، نام و ایمیل کارجو از آزمون می‌رود و نمره می‌ماند؛ با «پاک‌سازی کامل»، ردیف آزمون هم حذف می‌شود |

## ۵. مسیرهای HTTP

```http
GET  /api/assessments/templates?jobTitle=کارشناس فروش   → { templates, suggestedId }
GET  /api/assessments/templates/:id                     → پیش‌نمایش (بدون امتیاز گزینه‌ها)
GET  /api/assessments?resumeId=&jobId=                  → { items, summary }
GET  /api/assessments/:id                               → { assessment }
POST /api/assessments                                   → { assessment }   (این یک تماس است)
POST /api/assessments/:id/send                          → { assessment, emailed }
POST /api/assessments/:id/cancel                        → { assessment }
POST /api/assessments/:id/result                        → { assessment }   (نتیجهٔ بیرونی)

GET  /api/assessment/public/:token                      → { assessment, canAnswer }
POST /api/assessment/public/:token/start                → { assessment }
POST /api/assessment/public/:token/submit   { answers } → { assessment, thanks }
```

خطاها همیشه `{ error, code }` هستند: `RESUME_NOT_FOUND`, `TEMPLATE_NOT_FOUND`,
`ASSESSMENT_OPEN`, `ASSESSMENT_NOT_FOUND`, `ALREADY_COMPLETED`, `CANCELLED`, `EXPIRED`,
`ANSWERS_INCOMPLETE`, `EMAIL_NOT_CONFIGURED`, `EMAIL_FAILED`, `NO_EMAIL`, `BLIND_REVEAL_REQUIRED`.

## ۶. قرارداد ارائه‌دهندهٔ بیرونی (API با کلید)

ارائه‌دهندهٔ آزمون با **کلید API** همان سازمان کار می‌کند؛ نه نشست مرورگر:

```http
GET  /api/v1/assessments/:id            (scope: read)   → وضعیت و نتیجهٔ فعلی
POST /api/v1/assessments/:id/result     (scope: write)  → ثبت نتیجهٔ خودش
```

```bash
curl -X POST https://hovida.example.ir/api/v1/assessments/asm_9f2c1/result \
  -H "X-Hovida-Api-Key: hvd_sk_…" \
  -H "Content-Type: application/json" \
  -d '{"score":82,"dimensions":[{"id":"numerical","label":"استدلال عددی","score":82}],
       "note":"نتیجهٔ سنجمان — گزارش PDF در پرونده"}'
```

- النگوی پاسخ `source: "external"` می‌گیرد و همین در پنل و گزارش دیده می‌شود؛ چیزی که
  از بیرون آمده، به اسم خودش ثبت می‌شود.
- نمره باید ۰ تا ۱۰۰ باشد؛ یا نمره یا ابعاد لازم است، نه هیچ‌کدام خالی.
- یک آزمون **یک** نتیجه دارد؛ تلاش دوم ۴۰۹ می‌گیرد.
- ایمیل کارجو و فایل رزومه به ارائه‌دهنده داده نمی‌شود.

## ۷. اتصال به یک ارائه‌دهندهٔ آزمون هنجارشده

اگر مشتری آزمون معتبر (سنجمان، هایرکمپ، یا هر سرویس دیگر) می‌خواهد:

1. در **تنظیمات ← توسعه‌دهندگان** یک کلید با scope `write` بسازید و به ارائه‌دهنده بدهید.
2. هویدا آزمون را به‌عنوان «لینک» می‌سازد (همین صفحه) یا فقط یک ردیف نتیجه نگه می‌دارد.
3. ارائه‌دهنده پس از اتمام، نتیجه را با `POST /api/v1/assessments/:id/result` برمی‌گرداند.
4. نتیجه در پروندهٔ کارجو، در کنار رزومه و کارت ارزیابی، با برچسب «نتیجهٔ ارائه‌دهندهٔ بیرونی».

آنچه **در خود هویدا** ساخته نمی‌شود: بانک سؤال هنجارشده و گزارش روان‌سنجی. ساختن آن
کار سال‌ها و اعتبارسنجی علمی می‌خواهد؛ ادای آن را درنمی‌آوریم.

## ۹. آزمون‌های خودکار

- `npm run test:assessment` — ۷۰ بررسی: بانک، ساخت/ارسال/لغو، صفحهٔ عمومی، امتیازدهی
  (همه‌بهترین = ۱۰۰، همه‌بدترین مطابق کلید)، نمایهٔ پنج‌بُعدی با گزاره‌های معکوس،
  یک‌بارمصرف‌بودن، مسدودی بی‌طرف، نتیجهٔ بیرونی با کلید API، جداسازی فضای کاری.
- `npm test` — بررسی‌های واحد بانک (یکتایی شناسه‌ها، چهار گزینه، امتیاز ۰–۱۰، وجود یک
  پاسخ برتر، بُعدهای اعلام‌شده، آستانه‌های باند، جهت معکوس، پیشنهاد آزمون بر اساس نقش).
- `npm run test:mount` — دکمهٔ «آزمون و ارزیابی» در پروندهٔ کارجو و محتوای واقعی دیالوگ.
