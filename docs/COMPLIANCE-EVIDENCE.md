# بستهٔ شواهد انطباق — ISO/IEC 27001:2022 و SOC 2

> **جملهٔ اول، صریح:** هویدا گواهی ISO نمی‌دهد و گزارش SOC 2 صادر نمی‌کند. این ماژول
> «شواهد وضعیت» جمع می‌کند تا حسابرسِ شما کارش را سریع‌تر و ارزان‌تر انجام دهد. هر عددی که
> در بسته می‌آید، از وضعیت واقعی همان فضای کاری خوانده شده است و اگر شاهدی نباشد، کنترل
> «سند ارسال‌نشده» یا «جای خالی» می‌ماند.

**تنظیمات › انطباق و شواهد** — فقط مالک/مدیر. دلیلش ساده است: خروجی، فهرست همهٔ حساب‌ها با
نقش، ایمیل و وضعیت ورود دومرحله‌ای است.

---

## ۱) دو نوع کنترل، و تفاوتشان همه‌چیز است

| نوع | منبع شاهد | چطور سبز می‌شود |
| --- | --- | --- |
| **محصول** (`source: product`) | اندازه‌گیری زنده از همین فضا | فقط وقتی وضعیت واقعی همان باشد. دستی قابل سبزکردن نیست. |
| **سازمان** (`source: customer`) | فایل بارگذاری‌شده + اعلام کتبی | با بارگذاری سند و ثبت نام/تاریخ تصویب. HOVIDA درستی سند را تأیید نمی‌کند. |

**معنای چهار وضعیت:**

| وضعیت | معنی |
| --- | --- |
| `پوشش‌داده‌شده` | هست و شاهدش هم‌اکنون قابل ارائه است |
| `پوشش جزئی` | هست با یک محدودیت نام‌برده (مثلاً «۲FA هست، SSO نیست») |
| `جای خالی` | این محصول چنین کنترلی ندارد — واقعیت، نه «به‌زودی» |
| `سند ارسال نشده` | سندش را سازمان باید بدهد و هنوز نداده |

امتیاز وزنی: پوشش‌داده‌شده ۱، پوشش جزئی ۰٫۵، بقیه صفر. این عدد **بنچمارک نیست**؛ فقط
می‌گوید کجای کار ایستاده‌اید.

## ۲) فهرست کنترل‌ها (۱۸ کنترل، هر دو چارچوب)

| شناسه | عنوان | نوع | چه چیزی سنجیده می‌شود |
| --- | --- | --- | --- |
| A.5.15 | دسترسی بر پایهٔ نقش | محصول | تعداد اعضا/مدیران + تاریخ آخرین بازنگری دسترسی (پنجره ۱۸۰ روز) |
| A.5.16 | چرخهٔ عمر هویت | محصول | SCIM/SSO فعال است یا افزودن/حذف عضو دستی است |
| A.5.17 | احراز هویت | محصول | نسبت حساب‌های مدیر با ورود دومرحله‌ای + SSO |
| A.5.18 | مدیریت کلیدها | محصول | کلیدهای API فعال، کلید بی‌استفاده بیش از ۱۸۰ روز، وبهوک‌ها، رمزنگاری اعتبارنامه |
| A.8.24 | رمزنگاری | محصول | HTTPS بودن نشانی عمومی، AES-256-GCM اعتبارنامه‌ها، **رمزنگاری‌نداشتن فایل‌ها** |
| A.8.15 | ثبت رویداد | محصول | تعداد و تنوع رویداد ۳۰ روز گذشته + سقف/نبودِ WORM |
| A.8.16 | پایش ناهنجاری | محصول | **همیشه جای خالی** — محصول چنین موتوری ندارد |
| A.8.10 | حذف و نگه‌داری | محصول | سیاست نگه‌داری (روز/نوع)، آخرین اجرا، تعداد پاک‌سازی‌ها |
| A.5.34 | حریم خصوصی و رضایت | محصول | رضایت اجباری پورتال، پوشش رضایتِ استعلام سوءپیشینه، DSAR، مدت نگه‌داری |
| A.8.13 | پشتیبان‌گیری | محصول | فاصلهٔ آخرین پشتیبان، وجود بازیابی آزمایشی، نبودِ زمان‌بندی خودکار |
| A.6.1 | بررسی پیشینه | محصول | تعداد استعلام‌ها، پوشش رضایت، تصمیم انسانی مستند |
| CC5.3 | تفکیک وظایف | محصول | مراحل تأیید پیشنهاد، غربالگری بی‌طرف، کارتابل تأیید |
| A.5.1 | خط‌مشی امنیت اطلاعات | سازمان | سند + اعلام کتبی |
| A.5.19 | امنیت تأمین‌کنندگان | سازمان | فهرست اتصال‌ها (خودکار) + ارزیابی/قرارداد (شما) |
| A.5.24 | مدیریت رخداد | سازمان | رویه + سابقهٔ رخداد (شما) |
| A.5.29 | تداوم کسب‌وکار | سازمان | سند BCP/DR با RTO-RPO (شما) |
| A.6.3 | آموزش کارکنان | سازمان | سابقهٔ آموزش (شما) |
| A.7.1 | امنیت فیزیکی | سازمان | گزارش میزبان/دیتاسنتر (شما) |

هر کنترل در پنل سه چیز را نشان می‌دهد: **حسابرس چه می‌خواهد**، **این محصول چه می‌کند**
(شامل آنچه نمی‌کند)، و **چرا این وضعیت** — با اعدادی که همان لحظه خوانده شده‌اند.

## ۳) بازنگری دسترسی

یک گردش واقعی، نه یک تیک:

1. **شروع** — فهرست اعضا با نقش، ایمیل، وضعیت ۲FA و آخرین ورود **منجمد** می‌شود.
   حساب‌های دارای دسترسی مدیریتی، بدون ۲FA، یا بدون ورود ۹۰ روزه علامت می‌خورند.
2. **تأیید هر عضو** — با نام و تاریخ بازبین.
3. **بستن** — تا همه تأیید نشوند ممکن نیست؛ یادداشت پایان حداقل ۱۰ نویسه.
   در لحظهٔ بستن، اعداد (تعداد کل، تأییدشده، مدیران، بدون ۲FA) در `snapshot` قفل می‌شوند.

فقط یک بازنگری باز در هر زمان (`REVIEW_OPEN`). بازنگری کامل‌شده، کنترل A.5.15 را سبز
می‌کند — تا ۱۸۰ روز بعد که دوباره «پوشش جزئی» می‌شود و خودش یادآوری می‌کند.

## ۴) صدور بسته و اثر انگشت

```
POST /api/compliance/packs  { framework: 'iso27001' | 'soc2', scopeNote }
```

در لحظهٔ صدور، پنج فایل در ذخیره‌سازی نوشته می‌شوند و **همان‌ها** مبنای ZIPاند:

| فایل | محتوا |
| --- | --- |
| `README.md` | گزارش فارسی: خلاصه، محدودیت‌ها، هر کنترل با شاهد و علت، بازنگری دسترسی |
| `evidence.json` | همان داده به شکل ماشین‌خوان؛ **هش روی همین فایل** |
| `access-roster.csv` | فهرست حساب‌ها، نقش، ۲FA، آخرین ورود |
| `activity-summary.csv` | شمارش ماهانهٔ رویداد به تفکیک نوع — **بدون نام کارجو** |
| `SHA256SUMS` | هش همهٔ فایل‌ها، شامل پیوست‌ها |

* هش SHA-256 در جلد گزارش چاپ می‌شود و برابر است با هش بایت‌های `evidence.json`.
  حسابرس می‌تواند همان را بازمحاسبه کند.
* بسته **منجمد** است: تغییر تنظیمات بعدی، بستهٔ صادرشده را عوض نمی‌کند (تست این را ثابت
  می‌کند). برای وضعیت امروز، بستهٔ تازه صادر کنید.
* بستهٔ صادرشده در فید فعالیت با هش ثبت می‌شود.
* دانلود: `؟format=md | json | zip`.

### چه چیزی در بسته نیست

* **نام کارجو** — فایل فعالیت فقط ماه/نوع/تعداد دارد. لاگ حاوی نام، در سامانه می‌ماند و در
  بسته نمی‌آید.
* رمز، کلید، توکن یا اعتبارنامه — هیچ.
* اظهارنظر دربارهٔ کفایت کنترل‌ها؛ هر کنترل حداکثر می‌گوید «شاهدش این است».

## ۵) آنچه این ماژول ادعا نمی‌کند

| ادعا | واقعیت |
| --- | --- |
| «گواهی ISO 27001» | فقط نهاد صدوردهنده (CB) گواهی می‌دهد؛ این بسته شاهد است |
| «SOC 2 Type II» | گزارش حسابرس مستقل است؛ ما فقط شواهد را مرتب می‌کنیم |
| پایش ناهنجاری / SIEM | در محصول نیست — کنترل A.8.16 عمداً «جای خالی» است |
| آزمون نفوذ | انجام نمی‌دهیم و ادعا نمی‌کنیم |
| رمزنگاری فایل‌ها در حالت سکون | فایل رزومه/گواهی رمزنگاری درجا ندارد؛ کنترل A.8.24 همین را می‌گوید |
| پشتیبان خودکار زمان‌بندی‌شده | در محصول نیست؛ باید با cron/میزبان تنظیم شود |
| امنیت فیزیکی | با میزبان شماست؛ گزارش خودش را بارگذاری می‌کنید |

## ۶) دسترسی و داده

| اقدام | نقش لازم |
| --- | --- |
| خواندن بسته/کنترل‌ها/بازنگری‌ها | مالک یا مدیر |
| بارگذاری سند، اعلام کتبی، بازنگری، صدور/حذف بسته | مالک یا مدیر |
| عضو عادی | **۴۰۳** — حتی برای دیدن فهرست اعضا و وضعیت ۲FA |

* اسناد شاهد: PDF، تصویر، متن، docx/xlsx — حداکثر ۸ مگابایت، حداکثر ۱۰ سند برای هر کنترل.
  با کلید `compliance/<orgId>/att/<id>.<ext>` ذخیره می‌شوند و حذفشان بایت‌ها را برمی‌دارد.
* هر بارگذاری، اعلام، بازنگری و صدور بسته در فید فعالیت می‌آید.
* حذف فضای کاری، ردیف‌ها و همهٔ فایل‌های `compliance/<orgId>/` را پاک می‌کند.
* اعلام کتبی بیش از یک سال قدمت، خودکار «بیات» علامت می‌خورد و کنترل به «پوشش جزئی» برمی‌گردد.

## ۷) کدهای خطا

| کد | معنا |
| --- | --- |
| `FORBIDDEN` (403) | نقش کافی نیست |
| `CONTROL_NOT_FOUND` (404) | شناسهٔ کنترل در کاتالوگ نیست |
| `BAD_FILE_TYPE` (400) | پسوند پذیرفته‌شده نیست |
| `FILE_TOO_LARGE` (413) | بیش از ۸ مگابایت |
| `TOO_MANY_FILES` (409) | بیش از ۱۰ سند برای یک کنترل |
| `DECLARATION_TOO_SHORT` (400) | اعلام کمتر از ۲۰ نویسه |
| `REVIEW_OPEN` (409) | بازنگری باز دیگری وجود دارد |
| `MEMBERS_PENDING` (400) | عضو تأییدنشده مانده |
| `NOTE_REQUIRED` (400) | یادداشت پایان کوتاه است |
| `REVIEW_CLOSED` (409) | بازنگری بسته شده |
| `PACK_FILE_MISSING` (404) | فایل بسته در ذخیره‌سازی نیست |

## ۸) آزمون خودکار

`npm run test:compliance` — ۷۹ بررسی روی سرور واقعی، از جمله:

- ۴۰۳ عضو برای خواندن و صدور؛
- وضعیت صادقانهٔ اولیه: A.5.17 و A.8.16 و A.8.13 «جای خالی»، A.5.1 «سند ارسال‌نشده»؛
- تغییر واقعی: روشن‌کردن سیاست نگه‌داری A.8.10 را سبز می‌کند و خاموش‌کردنش برمی‌گرداند؛
- بازنگری: انجماد فهرست، علامت‌گذاری ۲FA، `MEMBERS_PENDING`، `NOTE_REQUIRED`، اسنپ‌شات،
  و سبزشدن A.5.15 بعد از آن؛
- سند: پسوند غیرمجاز رد، هش فایل درست، بارگذاری+اعلام = سبز، حذف = بازگشت به «سند ارسال‌نشده»؛
- بسته: هش ۶۴ نویسه‌ای، `files` شامل مانیفست و پیوست، هش جلد = هش JSONِ دریافتی،
  ZIP شامل هر شش فایل، پیوست بایت‌به‌بایت یکسان، مانیفست شامل هش هر دو؛
- **CSV فعالیت نام کارجو را ندارد** در حالی که نوع رویدادها را دارد؛
- انجماد: تغییر تنظیمات پس از صدور، بسته را عوض نمی‌کند؛ عضو تازه در فهرست بسته نمی‌آید؛
- جداسازی فضای کاری (۴۰۴)، حذف بسته و حذف سند، و سه رویداد در فید فعالیت.
