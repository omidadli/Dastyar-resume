# اتصال ایمیل سازمان (SMTP)

هویدا پیام‌ها را خودکار نمی‌فرستد. مسیر کار این است:

۱. در پنل کاندیدا → «پیام» → نوع پیام را انتخاب می‌کنید و پیش‌نویس (با هوش مصنوعی یا قالب آماده) ساخته می‌شود.
۲. متن را ویرایش می‌کنید.
۳. دکمهٔ **«ارسال با ایمیل سازمان»** ایمیل را از همان حساب سازمانی برای کارجو می‌فرستد.
   نسخهٔ ارسال‌شده در تاریخچهٔ ایمیل‌های کاندیدا با نام فرستنده و زمان می‌ماند و کاندیدا «ارسال‌شده» علامت می‌خورد.

## تنظیم (مدیر فضای کاری)

«تنظیمات ← اتصال‌ها ← ایمیل سازمان»:

| فیلد | نمونه | توضیح |
| --- | --- | --- |
| سرور SMTP | `smtp.gmail.com` | میزبان SMTP سرویس ایمیل سازمان |
| پورت | `465` (امن) یا `587` (STARTTLS) | |
| اتصال امن | روشن برای ۴۶۵ | TLS از ابتدای اتصال |
| نام کاربری | `hr@company.ir` | معمولاً همان نشانی کامل |
| رمز / App Password | `xxxx xxxx xxxx xxxx` | برای Gmail و Zoho الزامی است |
| نام فرستنده | «واحد منابع انسانی» | در صندوق ورودی گیرنده دیده می‌شود |
| نشانی فرستنده | `hr@company.ir` | باید مالکش باشید یا دامنه تأییدشده باشد |
| پاسخ به | `recruitment@company.ir` | اختیاری |

پیش از ذخیره، هویدا اتصال را با `verify()` آزمایش می‌کند؛ تنظیمات ناسالم ذخیره نمی‌شود.

### Gmail / Google Workspace
۱. تأیید دو مرحله‌ای را فعال کنید. ۲. در [App passwords](https://myaccount.google.com/apppasswords) یک رمز ۱۶ حرفی
بسازید. ۳. همان را در فیلد رمز بگذارید (رمز اصلی حساب کار نمی‌کند). ۴. `smtp.gmail.com`، پورت ۴۶۵، اتصال امن روشن.

### Outlook / Microsoft 365
`smtp.office365.com`، پورت ۵۸۷، اتصال امن خاموش (STARTTLS). اگر سازمان `SMTP AUTH` را بسته باشد، باید در
مرکز مدیریت Microsoft 365 برای همان صندوق فعال شود؛ در غیر این صورت از گزینهٔ «ایمیل سازمان» با سرور داخلی استفاده کنید.

### Zoho / Yandex / سرور داخلی
از اطلاعات SMTP پنل ایمیل خود استفاده کنید. برای سرور داخلی معمولاً `mail.company.local` یا یک IP و پورت ۲۵/۵۸۷ است.

## پرسش‌های رایج

- **«سرور ایمیل نام کاربری/رمز را نپذیرفت»**: App Password نساخته‌اید یا احراز هویت دومرحله‌ای خاموش است.
- **«اتصال برقرار نشد»**: پورت بسته است؛ بسیاری از میزبان‌ها پورت‌های ۴۶۵/۵۸۷ خروجی را مسدود می‌کنند (Render و
  Cloudflare معمولاً باز هستند). با پشتیبانی میزبان بررسی کنید.
- **«سرور نشانی فرستنده را قبول نکرد»**: نشانی فرستنده باید همان حساب یا دامنهٔ تأییدشده باشد (SPF/DKIM را تنظیم کنید
  تا ایمیل در Spam نرود).
- **سقف ارسال**: هر فضای کاری حداکثر ۱۲۰ ایمیل در ساعت از این مسیر می‌فرستد؛ فراتر از آن پاسخ ۴۲۹ می‌گیرید.
- **امنیت**: رمز SMTP با `APP_SECRET` رمزنگاری می‌شود (AES-256-GCM)، هرگز در پاسخ‌های API برنمی‌گردد و در اسنپ‌شات
  داده‌ها به‌صورت رمزشده ذخیره می‌شود. تغییر `APP_SECRET` باعث می‌شود رمز خوانده نشود و باید دوباره وارد شود.

## اگر ایمیل سازمان را وصل نکنید

همه‌چیز از کار نمی‌افتد: دکمهٔ «کپی متن»، لینک `mailto:`، واتساپ و پیامک همچنان کار می‌کنند و می‌توانید پیام را
«به‌عنوان ارسال‌شده» ثبت کنید. هویدا هرگز نشان نمی‌دهد ایمیلی فرستاده شده که واقعاً فرستاده نشده است.

## پشتیبان‌گیری

فایل پشتیبان کامل (`/admin › پشتیبان‌گیری و انتقال`) شامل تنظیمات اتصال هم هست، اما رمز SMTP فقط با `APP_SECRET`
همان نصب قابل خواندن است. اگر پشتیبان را روی سرور دیگری بازیابی می‌کنید و `APP_SECRET` را تغییر داده‌اید، باید رمز
ایمیل را یک‌بار دوباره وارد کنید (وضعیت «رمز ذخیره‌شده خوانده نشد» را می‌بینید).
