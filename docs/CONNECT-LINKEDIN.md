# اتصال جست‌وجوی استعداد به LinkedIn

هویدا در صفحهٔ **«جست‌وجوی استعداد»** (`/app/sourcing`) از شما می‌پرسد: «دنبال چه متخصصی با چه شرایطی هستید؟»، همان را
به یک کوئری جست‌وجو تبدیل می‌کند و افراد واجد شرایط — با تمرکز روی کسانی که وضعیت **Open to work** دارند — را نشان می‌دهد.
هر پروفایل را می‌توانید به یک فرصت شغلی اضافه کنید تا با همان موتور غربالگری رزومه‌ها سنجیده شود.

## چرا یک «سرویس» و نه یک آدرس ثابت؟

LinkedIn برای همهٔ حساب‌ها API جست‌وجوی افراد و خواندن پروفایل کامل ارائه نمی‌دهد. این قابلیت فقط در دسترس
**Talent Solutions / شرکای رسمی LinkedIn** یا سرویس‌های دادهٔ دارای مجوز است. اسکرپ کردن پروفایل‌ها هم خلاف
شرایط استفادهٔ LinkedIn و در بسیاری از کشورها ناقض قوانین حفاظت داده است.

به همین دلیل HOVIDA هیچ پروفایلی از خودش نمی‌سازد و داده‌ای را اسکرپ نمی‌کند؛ بلکه به «سرویسی که سازمان شما مجاز به
استفاده از آن است» وصل می‌شود. تا وقتی این اتصال تنظیم نشده باشد، جست‌وجو صادقانه با پیام «تنظیم نشده» متوقف می‌شود.

## راه‌اندازی (مدیر سامانه) — از داخل پنل، بدون فایل تنظیمات

۱. دسترسی سازمانی خود را از LinkedIn Talent Solutions (یا سرویس دادهٔ دارای مجوز) بگیرید: یک **URL جست‌وجو** و یک **توکن Bearer**.
۲. با حساب مدیر سامانه وارد **`/admin` › «اتصال‌ها»** شوید.
۳. در کارت «جست‌وجوی متخصص در LinkedIn» آدرس سرویس و توکن را بگذارید و **«آزمایش و ذخیره»** را بزنید.
   هویدا پیش از ذخیره یک درخواست آزمایشی به همان آدرس می‌فرستد؛ اگر پاسخ ندهد یا توکن را نپذیرد، ذخیره نمی‌شود و
   دلیل فارسی‌اش را نشان می‌دهد. بعد از ذخیره، همهٔ فضاهای کاری از همان سرویس جست‌وجو می‌کنند.
۴. برای تعویض توکن، همان کارت → مقدار تازه را در فیلد توکن بگذارید و ذخیره کنید. برای حذف، «حذف تنظیمات».

> توکن با AES-256-GCM رمزنگاری می‌شود، هرگز به مرورگر برنمی‌گردد (فقط `admi…-xyz` نمایش داده می‌شود) و در فایل
> پشتیبان هم به‌صورت رمزشده است.

### جایگزین: متغیرهای محیطی

اگر ترجیح می‌دهید (یا نصب خودکار است) می‌توانید همان دو مقدار را روی سرور بگذارید؛ فقط وقتی چیزی در پنل ذخیره نشده باشد
استفاده می‌شوند:

```bash
LINKEDIN_API_URL=https://api.your-provider.example/v1/people/search
LINKEDIN_ACCESS_TOKEN=...          # LINKEDIN_API_TOKEN هم پذیرفته می‌شود
# LINKEDIN_PROVIDER_LABEL=LinkedIn Talent API     # optional label shown in the UI
```

## دو نوع سرویس (از `/admin` › «اتصال‌ها»)

| نوع | چه چیزی وصل می‌شود | هم‌گام؟ |
| --- | --- | --- |
| **سرویس دارای مجوز / درگاه خودتان** | آدرس POST + توکن Bearer با قرارداد همین صفحه | یک درخواست، پاسخ فوری |
| **Apify (HarvestAPI)** | توکن Apify + شناسهٔ Actor، مثلاً `harvestapi/linkedin-profile-search` | ناهمگام: اجرا شروع می‌شود، صفحه وضعیت را می‌پرسد |

در حالت Apify، ورودی جست‌وجو از بریف ساخته می‌شود (`currentJobTitles` از عنوان نقش، `searchQuery` از مهارت‌ها،
`locations` با نام لاتین شهرها، `maxItems` چهار برابر تعداد درخواستی) و چون Actor فیلتر «آمادهٔ همکاری» ندارد،
فقط پروفایل‌هایی نگه داشته می‌شوند که خودش `openToWork: true` گزارش کرده است. شمار «بررسی‌شده / واجد شرایط»
در پیام همان جست‌وجو می‌آید. جزئیات: [`LINKEDIN-ACCESS-OPTIONS.md`](LINKEDIN-ACCESS-OPTIONS.md).

## قرارداد درخواست

HOVIDA یک `POST` به `LINKEDIN_API_URL` می‌فرستد:

```http
POST /v1/people/search
Authorization: Bearer <LINKEDIN_ACCESS_TOKEN>
Content-Type: application/json
```

```json
{
  "query": {
    "booleanQuery": "(\"حسابداری صنعتی\" OR \"بهای تمام‌شده\") AND (SAP OR \"Oracle EBS\") AND (تهران OR کرج)",
    "roleTitle": "کارشناس ارشد حسابداری صنعتی",
    "seniority": "کارشناس ارشد",
    "locations": ["تهران", "کرج"],
    "skills": ["حسابداری صنعتی", "SAP"],
    "mustHave": ["حداقل ۵ سال سابقه در تولید"],
    "keywords": ["بهای تمام‌شده", "انبار"],
    "openToWorkOnly": true
  },
  "limit": 25,
  "cursor": null
}
```

## قرارداد پاسخ

```json
{
  "total": 128,
  "nextCursor": null,
  "items": [
    {
      "id": "urn:li:member:12345",
      "fullName": "مریم کاظمی",
      "headline": "کارشناس ارشد حسابداری صنعتی | SAP",
      "location": "تهران، ایران",
      "profileUrl": "https://www.linkedin.com/in/maryam-kazemi",
      "openToWork": true,
      "currentCompany": "گروه صنعتی البرز",
      "experiences": [
        { "title": "کارشناس حسابداری صنعتی", "company": "گروه صنعتی البرز", "period": "۱۴۰۰ – اکنون", "description": "بهای تمام‌شده و گزارش‌های مدیریتی" }
      ],
      "education": ["کارشناسی ارشد حسابداری — دانشگاه تهران"],
      "skills": ["SAP", "اکسل پیشرفته"]
    }
  ]
}
```

فیلدهای جایگزین هم پذیرفته می‌شوند (سرویس‌ها یکسان نیستند): `name/full_name`، `url/publicProfileUrl`،
`isOpenToWork/open_to_work`، `experience/positions/workHistory`، `companyName/employer`، `dates/duration`، و
`skills` به‌صورت رشته یا `{name}`. آنچه سرویس نفرستد خالی می‌ماند — HOVIDA هیچ مقدار را حدس نمی‌زند.

پاسخ‌های خطا:

| وضعیت | رفتار HOVIDA |
| --- | --- |
| `401` / `403` | «توکن یا مجوز سازمان منقضی/نامعتبر است» |
| `429` | «سهمیهٔ درخواست امروز تمام شده؛ بعداً تلاش کنید» |
| `5xx` یا شبکه | «سرویس جست‌وجو پاسخ نداد» — جست‌وجو با وضعیت «ناموفق» در تاریخچه ذخیره می‌شود |

## آنچه سازمان شما باید بداند (انطباق)

- جست‌وجو فقط دربارهٔ **افرادی** است که سرویس شما مجاز به بازگرداندنشان است؛ فیلتر «Open to work» را سرویس اعمال می‌کند.
- افزودن یک پروفایل به فرصت شغلی، یک **رکورد کاندید** در فضای کاری شما می‌سازد؛ متن پروفایل به موتور تحلیل می‌رود و
  نتیجه با برچسب «افزوده‌شده از LinkedIn» و لینک پروفایل در سوابق می‌ماند.
- برای ذخیره یا پردازش دادهٔ شخصی، مبنای قانونی و سیاست نگه‌داری سازمان خود را رعایت کنید (مثلاً حذف کاندید پس از
  پایان فرایند؛ دکمهٔ «حذف رزومه» رکورد و فایل را کامل پاک می‌کند).
- هر جست‌وجو در «فعالیت تیم» ثبت می‌شود تا معلوم باشد چه کسی، چه وقتی، چه کوئری‌ای اجرا کرده است.

## آزمون بدون سرویس واقعی

یک سرویس ساختگی کوچک کافی است تا کل مسیر را امتحان کنید:

```bash
node -e '
require("http").createServer((req,res)=>{
  let b=""; req.on("data",c=>b+=c); req.on("end",()=>{
    res.writeHead(200,{"Content-Type":"application/json"});
    res.end(JSON.stringify({items:[{id:"1",fullName:"نمونه",headline:"حسابدار",profileUrl:"https://linkedin.com/in/x",openToWork:true,skills:["SAP"]}]}));
  });
}).listen(9911)'
LINKEDIN_API_URL=http://127.0.0.1:9911/search LINKEDIN_ACCESS_TOKEN=test npm run dev
```

فایل `scripts/integrations-api.test.ts` همین کار را به‌صورت خودکار انجام می‌دهد (`npm run test:integrations`).

## کنترل هزینه (اپافی)

هر جست‌وجوی اپافی پول است، پس هویدا سه محافظ دارد:

1. **سقف جست‌وجوی روزانه** — در همان کارت `اتصال‌ها` (پیش‌فرض ۲۰ جست‌وجو در شبانه‌روز، به وقت تهران، برای همهٔ فضاهای
   کاری با هم). رسیدن به سقف یعنی پاسخ ۴۲۹ با پیام «سقف جست‌وجوی روزانه این نصب پر شده است»؛ صفر = بی‌سقف.
   وارد کردن فایل CSV هیچ‌وقت شمرده نمی‌شود، چون هزینه‌ای ندارد.
2. **برآورد هزینه پیش از شروع** — پیام همان جست‌وجو می‌نویسد: «برآورد هزینهٔ این جست‌وجو در اپافی: ۰٫۸۰ دلار
   (۴ صفحه، ۱۰۰ پروفایل)» تا هیچ اجرایی غافلگیرکننده نباشد.
3. **توقف اجرای رهاشده** — اگر اجرا از ۱۰ دقیقه بگذرد، هویدا آن را در اپافی `abort` می‌کند (نه فقط چشم‌پوشی) و
   پیام می‌دهد: «اجرا در اپافی متوقف شد تا هزینهٔ بیشتری پرداخت نشود».

مصرف امروز در بالای صفحهٔ «جست‌وجوی استعداد» نمایش داده می‌شود («امروز ۳ از ۲۰ جست‌وجو…»).
