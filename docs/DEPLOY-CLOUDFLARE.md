# راهنمای استقرار هویدا روی Cloudflare

این راهنما هویدا را کامل روی Cloudflare راه می‌اندازد. بعد از آن دیگر به Render نیازی نیست. داده‌های فعلی هم بدون از دست رفتن هیچ رزومه‌ای منتقل می‌شوند.

---

## هویدا روی Cloudflare چطور کار می‌کند؟

```
مرورگر کاربر
   │
   ▼
Cloudflare Worker «hovida»  ── صفحه‌ها و فایل‌های برنامه (dist/) از لبه شبکه Cloudflare
   │  /api/*
   ▼
Container (همان سرور Node هویدا، ساخته‌شده از Dockerfile) — در اروپای غربی
   │
   ▼
R2 (فضای ذخیره‌سازی Cloudflare): داده‌ها در data/، رونوشت روزانه در backups/daily/
```

- **صفحه‌ها** از نزدیک‌ترین مرکز داده Cloudflare و با کش سرو می‌شوند، پس سریع باز می‌شوند. حتی وقتی سرور در حال بیدار شدن است، صفحه فوراً نمایش داده می‌شود.
- **سرور هویدا** همان کد فعلی است و داخل Cloudflare Containers اجرا می‌شود. همه قابلیت‌ها (همه قالب‌های فایل، کلیدهای هوش مصنوعی، پنل مدیریت) بدون تغییر کار می‌کنند.
- **داده‌ها و فایل‌های رزومه** در R2 نگهداری می‌شوند. هر تغییر چند لحظه بعد در R2 ذخیره می‌شود. اگر سرور خاموش یا جابه‌جا شود، داده‌ها سر جایشان می‌مانند.
- اگر سرور مدتی بی‌استفاده بماند (پیش‌فرض ۳۰ دقیقه) **به خواب می‌رود** و هزینه حافظه ندارد. اولین درخواست بعدی آن را در چند ثانیه بیدار می‌کند.
- هر شب ساعت ۱ بامداد به وقت تهران، یک **رونوشت خودکار** از داده‌ها در `backups/daily/` همان R2 ذخیره می‌شود. رونوشت‌های ۳۰ روز اخیر نگه داشته می‌شوند.

## هزینه (برآورد)

> این ارقام **برآورد** هستند و به میزان استفاده بستگی دارند. نرخ‌ها از صفحه قیمت‌گذاری Cloudflare (مهر ۱۴۰۵) گرفته شده‌اند.

| بخش | محاسبه | ماهانه |
| --- | --- | --- |
| پلن Workers Paid (الزامی برای Containers) | ثابت؛ شامل ۱۰ میلیون درخواست و سهمیه رایگان Containers | ۵ دلار |
| سرور (Container از نوع `basic`: ۱ گیگابایت رم، ¼ هسته) | حدود ۱۰ ساعت کار در روز ≈ ۲٫۵ تا ۳ دلار؛ روشن در تمام شبانه‌روز ≈ ۷ تا ۹ دلار | ۳ تا ۹ دلار |
| R2 | ۱۰ گیگابایت و یک میلیون نوشتن در ماه رایگان است | معمولاً ۰ |
| **جمع** | | **حدود ۸ تا ۱۴ دلار** |

## پیش‌نیازها

1. **حساب Cloudflare** با پلن **Workers Paid**. پرداخت با کارت بین‌المللی انجام می‌شود.
2. **دامنه اختصاصی.** آدرس‌های پیش‌فرض `*.workers.dev` در ایران فیلتر هستند، پس بدون دامنه، کاربران داخل ایران به سایت دسترسی ندارند. هر دامنه‌ای کار می‌کند، مثلاً `.ir` یا `.com`.
3. دسترسی به همین مخزن GitHub (`omidadli/Dastyar-resume`).

---

## گام ۱ — دامنه را به Cloudflare وصل کنید

1. دامنه را از هر ثبت‌کننده‌ای بخرید. برای `.ir` از نمایندگان ایرنیک و برای `.com` از هر ثبت‌کننده بین‌المللی.
2. در داشبورد Cloudflare روی **Add a domain** بزنید، نام دامنه را وارد کنید و پلن **Free** را انتخاب کنید.
3. Cloudflare دو **Nameserver** نشان می‌دهد. آن‌ها را در پنل ثبت‌کننده دامنه جایگزین Nameserverهای فعلی کنید.
4. صبر کنید تا وضعیت دامنه در Cloudflare **Active** شود. معمولاً چند دقیقه تا چند ساعت طول می‌کشد.

## گام ۲ — پلن Workers Paid و فضای R2

1. به **Workers & Pages** بروید، سپس **Plans** را باز کنید و **Workers Paid** را فعال کنید.
2. به **R2** بروید. اگر خواسته شد، R2 را فعال کنید؛ ۱۰ گیگابایت اول رایگان است.
3. روی **Create bucket** بزنید و این مقادیر را وارد کنید:
   - **Name:** `hovida-data` (دقیقاً همین؛ در `wrangler.jsonc` آمده است)
   - **Location:** `Automatic` یا `Western Europe (WEUR)`

   > اگر این مرحله را فراموش کنید، Wrangler در اولین استقرار خودش bucket را می‌سازد. ساختن دستی مطمئن‌تر است.

## گام ۳ — کد را آماده کنید

فایل‌های Cloudflare در Pull Request شماره ۶ هستند. اول آن را در `main` ادغام (Merge) کنید.

> **توجه:** با ادغام، Render هم خودکار نسخه جدید را مستقر می‌کند. این برای انتقال داده لازم است (گام ۸).
>
> اگر داده‌های نسخه قدیمی (تک‌سازمانی) را دارید، **قبل از ادغام** در Render، در بخش **Environment**، متغیر `LEGACY_OWNER_EMAIL` را برابر ایمیل حساب خودتان بگذارید. با این کار رزومه‌های قدیمی به همان حساب تحویل داده می‌شوند.

## گام ۴ — ساخت Worker از روی GitHub

با این روش هر بار که روی `main` تغییری push شود، Cloudflare نسخه جدید را خودکار مستقر می‌کند.

1. به **Workers & Pages** بروید و **Create** را بزنید. **Import a repository** را انتخاب کنید و حساب GitHub را وصل کنید.
2. مخزن `omidadli/Dastyar-resume` را انتخاب کنید و تنظیمات را این‌طور وارد کنید:

   | فیلد | مقدار |
   | --- | --- |
   | Project name | `hovida` (باید با `name` در `wrangler.jsonc` یکی باشد) |
   | Production branch | `main` |
   | Build command | `npm run build:cloudflare` |
   | Deploy command | `npx wrangler deploy` |
   | Root directory | خالی بگذارید |

3. **Save and Deploy** را بزنید.

**اولین استقرار چند دقیقه طول می‌کشد:** Cloudflare ایمیج Docker سرور را می‌سازد و آماده می‌کند. تا وقتی این کار تمام نشده، ممکن است سایت پیام «هویدا در حال راه‌اندازی است» نشان دهد. این طبیعی است.

## گام ۵ — متغیرها و کلیدهای محرمانه

**قبل از اولین بازدید از سایت**، به Worker «hovida» بروید و **Settings › Variables and Secrets › Add** را باز کنید. هر مورد را از نوع **Secret** اضافه کنید:

| نام | مقدار | ضرورت |
| --- | --- | --- |
| `APP_SECRET` | **دقیقاً همان مقدار Render** (Render › سرویس › Environment › `APP_SECRET`). اگر از Render منتقل نمی‌شوید، یک رشته تصادفی حداقل ۳۲ کاراکتری. | بسیار مهم |
| `ADMIN_EMAILS` | ایمیل خودتان، مثلاً `you@company.ir` (چند ایمیل را با ویرگول جدا کنید) | لازم |
| `DISABLE_DEMO` | `1` اگر دکمه «ورود به نسخه نمایشی» را نمی‌خواهید | اختیاری |
| `GEMINI_API_KEY` و `OPENAI_API_KEY` و … | کلیدهای هوش مصنوعی. بهتر است آن‌ها را در پنل مدیریت ثبت کنید. | اختیاری |

- **چرا `APP_SECRET` مهم است؟** کلیدهای هوش مصنوعی که در پنل مدیریت ثبت شده‌اند با این مقدار رمز شده‌اند. اگر همان مقدار Render را بگذارید، کلیدها بعد از انتقال بدون هیچ کاری کار می‌کنند. اگر مقدار دیگری بگذارید، کلیدها در پنل «ناخوانا» دیده می‌شوند و باید یک بار دوباره واردشان کنید.
- **بعدها هم می‌توانید این مقادیر را تغییر دهید.** هویدا تغییر را تشخیص می‌دهد و در اولین درخواست بعدی، سرور را با تنظیمات تازه در چند ثانیه دوباره راه‌اندازی می‌کند.
- دو متغیر عادی هم در `wrangler.jsonc` تعریف شده است:
  - `AI_PROVIDER`
  - `CONTAINER_SLEEP_AFTER`، یعنی مدت بی‌استفاده ماندن قبل از خواب سرور. اگر می‌خواهید سرور همیشه بیدار بماند، مثلاً `12h` بگذارید؛ هزینه بیشتر می‌شود.

## گام ۶ — دامنه را به Worker وصل کنید

1. در Worker «hovida»، **Settings › Domains & Routes › Add › Custom domain** را باز کنید.
2. دامنه یا زیردامنه دلخواه را وارد کنید، مثلاً `app.yourcompany.ir` یا خود `yourcompany.ir`.
3. چند دقیقه بعد سایت روی دامنه شما با SSL خودکار باز می‌شود. **از این به بعد فقط همین آدرس را به کاربران بدهید.**

## گام ۷ — اولین ورود و مدیر سامانه

1. سایت را روی دامنه خودتان باز کنید و با **همان ایمیلی که در `ADMIN_EMAILS` گذاشتید** ثبت‌نام کنید. این کار را **فوراً** انجام دهید، چون اولین کسی که با این ایمیل ثبت‌نام کند مدیر سامانه می‌شود.
2. به `/admin` بروید. پنل مدیریت باز می‌شود.

> راه دیگر: کد یک‌بارمصرف `HV-XXXX-XXXX-XXXX` را از لاگ بردارید (Worker «hovida» › **Observability › Logs**). وارد حساب خود شوید و کد را در `/admin` وارد کنید.

## گام ۸ — انتقال داده‌ها از Render

بهتر است این کار را در ساعتی انجام دهید که کسی با سامانه کار نمی‌کند. هر چیزی که بعد از گرفتن پشتیبان در Render ثبت شود، منتقل نمی‌شود.

1. **روی Render** (نسخه جدید، بعد از گام ۳): وارد شوید و به **پنل مدیریت › پشتیبان‌گیری و انتقال** بروید. **دریافت فایل پشتیبان** را بزنید. یک فایل ZIP دانلود می‌شود که همه داده‌ها و فایل‌های رزومه را دارد.
2. **روی Cloudflare:**
   1. با حساب مدیر گام ۷ به **پنل مدیریت › پشتیبان‌گیری و انتقال** بروید.
   2. **انتخاب فایل پشتیبان** را بزنید و فایل را انتخاب کنید.
   3. فایل بارگذاری و بررسی می‌شود و خلاصه محتوای آن را می‌بینید: تعداد فضاهای کاری، کاربران، رزومه‌ها و فایل‌ها.
   4. کلمه **«بازیابی»** را بنویسید و **بازیابی داده‌ها** را بزنید.
3. بعد از پایان، همه از حساب خارج می‌شوند. **با همان ایمیل و رمز عبوری که در Render داشتید** وارد شوید. حساب موقتی که در گام ۷ ساختید با داده‌های پشتیبان جایگزین شده است.
4. چند رزومه را باز کنید، فایل اصلی‌شان را ببینید و مطمئن شوید همه چیز سر جایش است.

نکته‌ها:

- اگر قبل از گرفتن پشتیبان «حالت نگهداری» را در Render روشن کرده باشید، این تنظیم هم منتقل می‌شود. بعد از بازیابی، آن را در **پنل مدیریت › تنظیمات سامانه** خاموش کنید.
- اگر `APP_SECRET` با Render یکی نیست، کلیدهای هوش مصنوعی را در **پنل مدیریت › کلیدهای هوش مصنوعی** دوباره وارد کنید.
- فایل پشتیبان اطلاعات شخصی متقاضیان را دارد. بعد از انتقال آن را در جای امنی نگه دارید و نسخه‌های اضافی را پاک کنید.

## گام ۹ — خاموش کردن Render

وقتی مطمئن شدید همه چیز روی Cloudflare درست کار می‌کند:

1. در Render سرویس `seilaneh-resume-screener` را باز کنید و **Suspend** را بزنید تا هزینه‌اش قطع شود. چند هفته صبر کنید و بعد آن را حذف کنید. دیسک Render تا حذف سرویس باقی می‌ماند.
2. فایل `render.yaml` در مخزن می‌ماند و مزاحمتی ندارد. هر وقت خواستید می‌توانید دوباره روی Render مستقر کنید.

## به‌روزرسانی‌های بعدی

هر تغییری که در `main` ادغام شود، خودکار روی Cloudflare مستقر می‌شود. سرور قبل از خاموش شدن، درخواست‌های در حال انجام را تمام می‌کند و داده‌ها را ذخیره می‌کند. نسخه جدید در چند ثانیه بالا می‌آید.

## روش جایگزین: استقرار از رایانه خودتان

این روش به **Docker Desktop** نیاز دارد:

```bash
npm ci
npx wrangler login
npm run cf:deploy          # ساخت برنامه، ساخت ایمیج Docker و استقرار
npx wrangler secret put APP_SECRET
npx wrangler secret put ADMIN_EMAILS
```

## پشتیبان‌گیری

- **پشتیبان کامل (پیشنهادی):** هر چند وقت یک بار از **پنل مدیریت › پشتیبان‌گیری و انتقال** یک فایل ZIP بگیرید و جای امنی نگه دارید. این فایل همه چیز را دارد و روی هر سرور هویدا قابل بازیابی است.
- **رونوشت خودکار روزانه:** در R2، مسیر `hovida-data › backups/daily/` قرار دارد و رکوردها را دارد، نه فایل‌های اصلی رزومه. برای مواقع اضطراری است و بازگرداندن آن کار یک متخصص فنی است.
- هر بار بازیابی، یک نسخه از داده‌های قبلی را هم در `data/backups/pre-restore/` نگه می‌دارد. سه نسخه آخر نگه داشته می‌شوند.

## عیب‌یابی

| مشکل | راه‌حل |
| --- | --- |
| پیام «هویدا در حال راه‌اندازی است» | بعد از اولین استقرار، آماده‌سازی چند دقیقه طول می‌کشد. بعد از خواب سرور، بیدار شدن چند ثانیه طول می‌کشد. اگر چند دقیقه ادامه داشت، لاگ‌ها را ببینید. |
| سایت از ایران باز نمی‌شود | از آدرس `workers.dev` استفاده نکنید و دامنه اختصاصی را وصل کنید (گام ۶). |
| ساخت (Build) با خطای نام Worker متوقف شد | نام پروژه در داشبورد باید `hovida` باشد، یا `name` را در `wrangler.jsonc` با نام پروژه یکی کنید. |
| ساخت با خطای پیدا نشدن `dist` متوقف شد | Build command باید `npm run build:cloudflare` باشد (گام ۴). |
| لاگ‌ها کجاست؟ | Worker «hovida» › **Observability › Logs**. وضعیت سرور در **Workers & Pages › Containers** است. |
| داده‌ها کجا ذخیره می‌شوند؟ | R2 › `hovida-data` › `data/`، شامل `hovida-store.json` و پوشه `resumes/`. |
| سرور قوی‌تر لازم دارم | در `wrangler.jsonc` مقدار `instance_type` را از `basic` به `standard-1` تغییر دهید (نیم هسته، ۴ گیگابایت رم). |

## تنظیمات پیشرفته (`wrangler.jsonc`)

- `instance_type`: اندازه سرور (`basic` پیش‌فرض است).
- `max_instances: 1`: هویدا داده‌های در حال کار را در یک فرایند نگه می‌دارد. این عدد را تغییر ندهید.
- `constraints.regions: ["WEUR"]`: سرور در اروپای غربی اجرا می‌شود. این منطقه به مسیرهای بین‌المللی ایران نزدیک است و Gemini در آن در دسترس است.
- `triggers.crons`: زمان رونوشت روزانه (به وقت UTC؛ `30 21 * * *` یعنی ۱ بامداد تهران).
- `vars.CONTAINER_SLEEP_AFTER`: مدت بی‌استفاده ماندن قبل از خواب سرور.

## برای توسعه‌دهندگان

| فایل | توضیح |
| --- | --- |
| `cloudflare/worker.ts` | ورودی Worker، کلاس Container، بازراه‌اندازی خودکار پس از تغییر تنظیمات، رونوشت شبانه |
| `cloudflare/router.ts` | مسیریابی لبه: صفحه‌ها، فایل‌های برنامه، `/api`، IP واقعی کاربر، خطای فارسی هنگام راه‌اندازی |
| `cloudflare/storage-handler.ts` | پروتکل ذخیره‌سازی سرور روی R2، با نوشتن شرطی و کنترل MD5 |
| `server/storage.ts` | دو راه‌انداز ذخیره‌سازی سرور: دیسک (`DATA_DIR`) یا راه دور (`STORAGE_DRIVER=remote`) |
| `server/backup.ts` و `server/zip.ts` | پشتیبان کامل و بازیابی |
| `Dockerfile` | ایمیج سرور؛ روی هر میزبان Docker دیگری هم کار می‌کند |

آزمون‌ها، بدون نیاز به Docker و حساب Cloudflare:

```bash
npm test                       # شامل آزمون‌های ذخیره‌سازی (دیسک و راه دور)
npm run build
npm run test:backup            # پشتیبان کامل و بازیابی سرتاسری
npm run test:cloudflare        # Worker، مسیریابی لبه و R2 در محیط واقعی workerd
npm run cf:typecheck
```

اجرای محلی هویدا دقیقاً مثل Cloudflare (ذخیره‌سازی راه دور):

```bash
node scripts/mock-storage-server.mjs --port 8790 &
STORAGE_DRIVER=remote STORAGE_URL=http://127.0.0.1:8790 npm run dev
```
