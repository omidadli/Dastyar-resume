# تجربهٔ کارجو — نظرسنجی و NPS

هر کارجو در پایان مسیر یک چیز را می‌داند که هیچ‌کس در سازمان نمی‌داند: **این فرایند از نگاه او چطور بود.** هویدا همان را در دو دقیقه از او می‌پرسد و به یک عدد قابل پیگیری تبدیل می‌کند.

| کجا | چه کاری |
| --- | --- |
| پروندهٔ کارجو › «اطلاعات بیشتر» › دکمهٔ **نظرسنجی تجربه** | ساخت لینک، ارسال با ایمیل سازمان، کپی لینک، دیدن پاسخ |
| صفحهٔ عمومی `/survey/<token>` | همان چیزی که کارجو می‌بیند (بدون حساب کاربری) |
| گزارش‌ها › کارت **تجربهٔ کارجو** | NPS، نرخ پاسخ، ترکیب پاسخ‌ها، سه بُعد، نظرهای متنی |
| `GET /api/surveys/report` | همان اعداد از API (برای BI) |

---

## ۱) چه چیزی پرسیده می‌شود؟

**یک سؤال اصلی (۰ تا ۱۰):**

> «چقدر احتمال دارد تجربهٔ خود را به یک دوست معرفی کنید؟»

متن با لحظهٔ مسیر تغییر می‌کند (پس از درخواست / مصاحبه / نتیجهٔ منفی / استخدام) تا جمله بی‌ربط نباشد.

**سه سؤال ۱ تا ۵ (اختیاری):**

| بُعد | پرسش |
| --- | --- |
| روشن بودن مراحل | می‌دانستید در هر مرحله چه انتظاری داشته باشید؟ |
| سرعت و اطلاع‌رسانی | به‌موقع خبر دادیم و منتظر نماندید؟ |
| رفتار محترمانه | در همهٔ تماس‌ها با شما محترمانه رفتار شد؟ |

**یک کادر متن آزاد (اختیاری، تا ۱۲۰۰ کاراکتر).**

سؤال‌های ۱–۵ عمداً ثابت‌اند: با تغییر متن، عدد سال بعد با سال قبل قابل مقایسه نیست.

---

## ۲) NPS دقیقاً چطور حساب می‌شود؟

| امتیاز | دسته |
| --- | --- |
| ۹–۱۰ | معرفی‌کننده (promoter) |
| ۷–۸ | بی‌طرف (passive) |
| ۰–۶ | منتقد (detractor) |

```
NPS = (تعداد معرفی‌کننده ÷ تعداد پاسخ‌ها − تعداد منتقد ÷ تعداد پاسخ‌ها) × ۱۰۰
```

عددی بین **−۱۰۰** و **۱۰۰**. پاسخ‌های بی‌امتیاز (کسی که فقط سؤال‌های ۱–۵ را زده) در NPS نمی‌آیند اما در **نرخ پاسخ** دیده می‌شوند.

مثال از آزمون واقعی محصول: دو پاسخ، یکی ۹ و یکی ۳ → ۱ معرفی‌کننده، ۱ منتقد، ۰ بی‌طرف → **NPS = ۰**.

**چیزهایی که گزارش عمداً نشان می‌دهد و رقبا پنهان می‌کنند:**

* «فرستاده‌شده» در برابر «باز شده» در برابر «پاسخ داده» — لینکی که باز نشده، بی‌طرف نیست؛ بی‌پاسخ است.
* NPS منفی با رنگ قرمز، نه گرد‌شده به «خوب».
* NPS به تفکیک لحظه (مثلاً بعد از نتیجهٔ منفی به‌شدت پایین‌تر است — همان‌جا باید کار کرد).

## ۳) جریان کار

```
ساخت لینک ──▶ ارسال با ایمیل سازمان ──▶ کارجو باز می‌کند ──▶ پاسخ می‌دهد ──▶ گزارش
   │                  │                                    │
   │                  └─ اگر SMTP وصل نباشد: پیام صادقانه + کپی لینک
   └─ هیچ ایمیلی فرستاده نمی‌شود تا کسی دکمهٔ ارسال را نزند
```

### ساخت

پروندهٔ کارجو › «نظرسنجی تجربه» › لحظهٔ مسیر را انتخاب کنید › **ساخت لینک نظرسنجی**.

* برای هر کارجو هم‌زمان فقط **یک** نظرسنجی باز مجاز است (پاسخ `409 SURVEY_OPEN`)؛ برای ارسال دوباره از همان لینک استفاده می‌شود.
* لینک **۳۰ روز** باز است.
* توکن تصادفی ۲۴ بایتی است و در پاسخ API به‌صورت فیلد جدا برنمی‌گردد؛ فقط داخل `url` می‌آید.

### ارسال

دکمهٔ «ارسال با ایمیل سازمان» نامهٔ کوتاه را از **صندوق خود سازمان** می‌فرستد (SMTP تنظیم‌شده در تنظیمات › اتصال‌ها). نامه شامل نام کارجو و عنوان فرصت است، نه یک متن عمومی.

حالت‌هایی که درست گزارش می‌شوند:

| وضعیت | پاسخ |
| --- | --- |
| SMTP وصل نیست | `409 EMAIL_NOT_CONFIGURED` — «ایمیل سازمان وصل نیست؛ لینک را کپی کنید» |
| کارجو ایمیل ندارد | `409 NO_EMAIL` — لینک را دستی بفرستید |
| قبلاً پاسخ داده | `409 ALREADY_ANSWERED` |

پس از هر ارسال موفق، یک خط `survey.sent` در فید فعالیت تیم و (در صورت اشتراک) در اسلک/تیمز و وب‌هوک می‌آید.

### پاسخ

صفحهٔ عمومی `/survey/<token>`:

1. باز شدن صفحه یک بار ثبت می‌شود (`opened`)، تا «فرستاده» و «باز شده» از هم جدا بمانند.
2. امتیاز ۰–۱۰ اجباری، سه بُعد و متن آزاد اختیاری.
3. یک بار پاسخ؛ بار دوم `409 ALREADY_ANSWERED` و صفحه «سپاسگزاریم» نشان می‌دهد.
4. لینک منقضی یا لغوشده: `409 EXPIRED` با پیام محترمانه.

هیچ داده‌ای از کارجو در صفحهٔ عمومی بیرون نمی‌رود: نه ایمیل، نه شناسهٔ داخلی، نه نام سایر کارجویان.

## ۴) گزارش

**گزارش‌ها › تجربهٔ کارجو** (با همان بازهٔ بالای صفحه: ۳۰ روز / ۹۰ روز / یک سال / همه)

| عدد | معنی |
| --- | --- |
| NPS | توضیح بالا |
| نرخ پاسخ | پاسخ‌داده ÷ فرستاده‌شده |
| ترکیب پاسخ‌ها | معرفی‌کننده / بی‌طرف / منتقد |
| سه بُعد | میانگین هر بُعد از ۵ |
| به تفکیک لحظه | NPS هر مرحله از مسیر |
| آخرین نظرها | متن‌های واقعی، با امتیاز و تاریخ |

API:

```bash
curl -H "X-Hovida-Session: …" "https://hovida.example.ir/api/surveys/report?range=365"
```

## ۵) حریم خصوصی و نگه‌داری

* پاسخ‌ها **به نتیجهٔ درخواست گره نمی‌خورند**؛ در متن نامه هم همین را به کارجو می‌گوییم. (اگر امتیاز روی تصمیم اثر بگذارد، دیگر نظر صادقانه نیست.)
* پاسخ فقط برای اعضای همان فضای کاری قابل خواندن است؛ صفحهٔ عمومی هیچ‌گاه پاسخ‌ها را نشان نمی‌دهد.
* با **ناشناس‌سازی** (تنظیمات › نگه‌داری داده): امتیاز و اعداد می‌مانند، اما نام کارجو و متن نظر پاک می‌شود.
* با **پاک‌سازی کامل داده (DSAR)**: همهٔ نظرسنجی‌های آن کارجو حذف می‌شوند و تعدادشان در پاسخ `erased.surveys` برمی‌گردد.
* حذف فرصت شغلی یا کارجو، نظرسنجی‌های مربوط را هم پاک می‌کند.

## ۶) چه چیزی این نیست

| نیست | توضیح |
| --- | --- |
| نظرسنجی خودکار پس از هر تصمیم | عمداً نیست: هر نامه به کارجو تصمیم انسانی است. اگر خواستید، از «اتوماسیون جذب» یک پیشنهاد برای تأیید بسازید |
| eNPS کارکنان | این نظرسنجی دربارهٔ **فرایند جذب** است، نه رضایت شغلی کارکنان فعلی |
| جایگزین مصاحبهٔ خروج | یک عدد و یک جمله است، نه گفت‌وگوی ساختاریافته |
| عدد مقایسه‌ای با بازار | NPS بدون گروه مرجع فقط برای مقایسهٔ **خودتان با خودتان** در زمان معنا دارد؛ عدد ۴۰ برای یک شرکت ۲۰ نفره و یک برند بزرگ یکی نیست |
