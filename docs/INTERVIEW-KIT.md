# کیت مصاحبه (بانک پرسش و راهنمای شنیدن)

> **چکیده:** برای هر فرصت شغلی، هویدا یک کیت مصاحبه می‌سازد: بخش‌بندی‌شده، با زمان
> پیشنهادی، و برای هر پرسش دو چیز — **چه چیزی را بشنوید** و **چه چیزی علامت هشدار است**.
> کیت از سه منبع ساخته می‌شود: بانک پرسش (۳۰ بستهٔ تخصصی / ۳۰ نقش / ۷۰ پرسش)، معیارهای
> خودِ همان فرصت شغلی، و رزومهٔ کارجو وقتی از داخل پرونده بازش می‌کنید. هیچ‌چیز ذخیره
> نمی‌شود؛ هر بار از دادهٔ همان لحظه ساخته می‌شود.

---

## ۱. کجا باز می‌شود؟

| مسیر | نتیجه |
| --- | --- |
| **فرصت شغلی › دکمهٔ «کیت مصاحبه»** | کیت عمومی نقش، بدون نام کارجو |
| **پنل کارجو › «کیت مصاحبه»** (یا منوی همان ردیف) | همان کیت + دو بخش مخصوص همین رزومه |
| نشانی مستقیم | `/app/jobs/<jobId>/kit?c=<resumeId>` |

اگر کارجو متعلق به همان فرصت نباشد، سرور صریح رد می‌کند: «این کارجو به این فرصت شغلی
مربوط نیست.» — نه کیت ناقص، نه سکوت.

## ۲. کیت از چه چیزی ساخته می‌شود؟

```
باز کردن انگیزه (۳ پرسش)
      ↓
یک پرسش لنگر از خود نقش  ←  «یک قطعی شبکه که خودت حل کردی…»
      ↓
تا ۴ بستهٔ بدنه:  اول بسته‌های نقش (حداکثر ۲)  و بعد بسته‌های معیارها (سنگین‌ترین اول)
      ↓
[اگر کارجو انتخاب شده]  پرسش از خود این رزومه  +  تأیید پیش از تصمیم
      ↓
بستن جلسه (یک پرسش + سه خط برای بعد از جلسه)
```

- **بستهٔ «دستاورد و نقش واقعی در آن»** همیشه هست: هر نقشی کار قابل‌نمایش دارد.
- **نقش** از عنوان شغل خوانده می‌شود (با بلندترین نام جایگزین، تا «فرانت‌اند» به «بک‌اند»
  تبدیل نشود). نقش ناشناخته ⇒ کیت باز هم ساخته می‌شود، فقط از معیارها.
- **معیارها** با تطبیق کلمه‌به‌کلمه (مرز واژه) خوانده می‌شوند: «تولید محتوا» بستهٔ محتوا
  را می‌آورد، نه بستهٔ کارخانه؛ «نگهداری مشتری» بستهٔ تعمیرات را نمی‌آورد؛ «برقراری
  ارتباط» با «برق» جور نمی‌شود.
- اگر یک بسته از دو معیار بیاید، **یک‌بار** می‌آید و با سنگین‌ترین معیارش ثبت می‌شود.
- کیت عمومی حدود **۵۳ دقیقه** و ۱۴ پرسش است؛ با کارجو بلندتر می‌شود. زمان هر بخش
  جمع زده می‌شود و در خط چهارم «چطور استفاده کنیم» می‌آید.

## ۳. چرا «چه بشنوید» و «علامت هشدار» نوشته شده؟

چون اکثر کیت‌های مصاحبه در بازار فقط سؤال می‌دهند و انتخاب سؤال را به حافظهٔ مصاحبه‌گر
می‌سپارند. اینجا هر پرسش دو خط دارد:

- **بشنوید:** پاسخ قوی چه دارد (مثال مشخص، عدد، نقش خودِ فرد، نتیجه).
- **علامت هشدار:** نشانهٔ پاسخ تُنُک («ما انجام دادیم» بدون «من»)، یا ادعایی که با
  رزومه جور نیست.

مصاحبه‌گر لازم نیست متخصص آن حوزه باشد؛ راهنمای شنیدن، همان کاری است که یک مدیر فنی
باتجربه در جلسه می‌کند. ولی صریح می‌گوییم: این **راهنمای شنیدن** است، نه پاسخنامه؛
قضاوت نهایی با انسان است و امتیاز همان‌جا در کارت ارزیابی ثبت می‌شود.

## ۴. با رزومه، کیت شخصی می‌شود

دو بخش اضافه می‌شود که هیچ بانک عمومی نمی‌تواند بسازد:

- **پرسش از خود این رزومه** — از شکاف‌ها و ادعاهای همان رزومه ساخته می‌شود
  (مثلاً جهش شغلی کوتاه، مهارت اعلام‌شده بدون شاهد، یا فاصلهٔ زمانی).
- **تأیید پیش از تصمیم** — پرسش‌هایی که پیش از رفتن به مرحلهٔ بعد باید جواب بگیرند.

در حالت **غربالگری بی‌طرف**، کیت نام کارجو را نشان نمی‌دهد: برچسب پایدار («کارجوی ۲۳۶۸»)
جایش می‌آید و پرسش‌ها هم بدون نام نوشته می‌شوند. پنهان‌سازی روی سرور است، پس در پاسخ
JSON هم نامی نیست.

## ۵. خروجی گرفتن

- **کپی متن** — کل کیت به‌صورت متن مرتب (برای پیست در ورد، اسلک، یا چاپ).
- **چاپ** — یک نسخهٔ کاغذی تمیز: نوار کنار، منو و دکمه‌ها حذف می‌شوند، هر بخش از
  وسط صفحه نمی‌شکند، و سرصفحهٔ اختصاصی چاپ می‌آید.
- نتیجهٔ جلسه در **کارت ارزیابی** همان کارجو ثبت می‌شود؛ کیت عمداً ذخیره نمی‌شود تا
  نسخهٔ قدیمی جایش را به معیارهای امروز ندهد.

## ۶. API

```http
GET /api/jobs/<jobId>/interview-kit              → کیت عمومی نقش
GET /api/jobs/<jobId>/interview-kit?resumeId=<r> → کیت شخصی همان کارجو
GET /api/interview-kit/bank                      → فهرست بانک (۳۰/۳۰/۷۰)
```

نمونهٔ کوتاه‌شده:

```json
{
  "kit": {
    "jobId": "job_…",
    "roleTitle": "کارشناس فروش",
    "departmentName": "فروش",
    "durationMin": 53,
    "howTo": ["هر سؤال را با «مثال واقعی بزن» ادامه بدهید؛ …"],
    "sections": [
      {
        "id": "s-motivation",
        "title": "انگیزه و واقعیت‌های این شغل",
        "why": "پیش از هر مهارتی، باید بدانیم چرا این نقش و چرا حالا.",
        "minutes": 5,
        "questions": [
          {
            "id": "motivation-1",
            "text": "…",
            "listen": "…",
            "red": "…",
            "criterionId": null,
            "source": "bank"
          }
        ]
      }
    ],
    "criteria": [{ "id": "c1", "title": "مذاکره و بستن قرارداد فروش", "weight": 80, "mustHave": true }],
    "thresholds": { "interview": 75, "review": 50 },
    "candidate": { "resumeId": "res_…", "label": "کارجوی ۲۳۶۸", "score": 81, "category": "INTERVIEW" },
    "closing": ["قدم بعدی و زمان پاسخ را در همان جلسه بگویید؛ …"],
    "matched": ["sales", "negotiation", "targets", "discovery", "crm"]
  }
}
```

کدهای خطا: `404` فرصت شغلی ناشناخته، `404` رزومهٔ ناشناخته، `400` کارجوی متعلق به
فرصتی دیگر، `401` بدون ورود.

## ۷. چیزهایی که عمداً نیست

- **ذخیرهٔ نسخه‌ای از کیت** — معیارها عوض می‌شوند؛ کیتِ ذخیره‌شده به سرعت دروغ می‌گوید.
- **امتیازدهی خودکار از پاسخ‌ها** — بدون ضبط و رونویسی، چنین چیزی ادعاست. تصمیم با
  کارت ارزیابی انسانی است.
- **پرسش‌های شخصیتی/روان‌سنجی** — نیازمند بانک اعتبارسنجی‌شده و مجوز است، نه چند
  سؤال اینترنتی (به [`COMPETITORS.md`](COMPETITORS.md) بخش «جای خالی‌ها» نگاه کنید).

## ۸. آزمون

```bash
npx tsx scripts/interview-kit-api.test.ts   # یا: npm run test:kit
```

حدود ۴۵ شرط، از جمله: هر پرسش «بشنوید» و «علامت هشدار» دارد؛ کیت فروش بستهٔ شبکه
را نمی‌آورد؛ نقش ناشناخته کیت خالی نمی‌دهد؛ معیارهای دستی همان معیارها را می‌آورند؛
در حالت بی‌طرف نام کارجو در پاسخ نیست. اجزای بانک در `scripts/unit.test.ts` هم آزمون
دارند (تطبیق نقش، مرز واژه، سقف چهار بسته، ترتیب بر اساس وزن).
