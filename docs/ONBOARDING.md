# تحویل پس از استخدام

> استخدام با امضای پیشنهاد تمام نمی‌شود؛ تازه شروع می‌شود. این بخش همان چیزی است که معمولاً
> در یک گروه واتس‌اپ و یک دفتر کاغذی گم می‌شود: لپ‌تاپ، حساب ایمیل، قرارداد، معرفی به تیم و
> «روز اول چه کسی دنبالش است؟»

جای این صفحه در سایت: نوار کنار ← **تحویل پس از استخدام** (`/app/onboarding`).

---

## ۱. چطور شروع می‌شود؟

دو راه دارد و هر دو به یک چیز می‌رسند:

| راه | چه اتفاقی می‌افتد |
| --- | --- |
| **پیشنهاد شغلی پذیرفته می‌شود** (مسیر معمول) | همان لحظه، برنامهٔ تحویل خودکار ساخته می‌شود: روز شروع از خودِ پیشنهاد خوانده می‌شود، مسئول تحویل نام امضاکنندهٔ پیشنهاد است و در یادداشت نوشته می‌شود که «به‌طور خودکار از پذیرش پیشنهاد ساخته شد». |
| **دکمهٔ «برنامهٔ تازه»** | از فهرست کارجویانی که در ستون **«استخدام‌شده»** تختهٔ جذب هستند یکی را انتخاب می‌کنید. اگر تاریخ شروع را خالی بگذارید، دو هفته بعد از امروز گذاشته می‌شود. |

**قاعدهٔ سخت:** برای کسی که هنوز در حال بررسی است برنامه ساخته نمی‌شود. سرور با
`409 NOT_HIRED` جواب می‌دهد و می‌نویسد که اول باید پیشنهاد فرستاده و پذیرش ثبت شود. دلیلش
ساده است: برنامهٔ تحویل یعنی «این فرد استخدام شد»؛ اگر این تصمیم گرفته نشده باشد، ساختن
چک‌لیست فقط وعدهٔ لپ‌تاپ به کسی است که هیچ‌کس درباره‌اش تصمیم نگرفته.

برای هر کارجو در هر لحظه فقط **یک برنامهٔ باز** وجود دارد (`409 PLAN_EXISTS`). برنامهٔ لغوشده
جلوی ساختن برنامهٔ تازه را نمی‌گیرد.

## ۲. تاریخ شروع

- تاریخ به **شمسی** وارد و نمایش داده می‌شود: `۱۴۰۵/۰۹/۰۱`.
- ورودی با ارقام فارسی و انگلیسی هر دو پذیرفته است.
- تاریخ ناموجود (مثلاً ماه ۱۳) با `400 BAD_START_DATE` رد می‌شود و **به تاریخ پیش‌فرض تبدیل
  نمی‌شود** — تاریخ اشتباه نباید بی‌صدا درست شود.
- زیر هر برنامه، شمارش روز تا شروع نوشته می‌شود: «۳ روز تا روز اول»، «امروز روز اول است»،
  یا «۵ روز از شروع گذشته».
- شمارش بر اساس **روز تهران** است، نه ساعت سرور.

## ۳. چک‌لیست

نه مورد پیش‌فرض، به همان ترتیبی که معمولاً از دست می‌رود:

1. قرارداد و الحاقیه‌ها امضا شد
2. مدارک هویتی و بیمه تحویل گرفته شد
3. حساب ایمیل سازمانی ساخته شد
4. دسترسی به سامانه‌های کاری داده شد
5. لپ‌تاپ و تجهیزات تحویل داده شد
6. میز و فضای کار آماده شد
7. به تیم معرفی شد (جلسهٔ روز اول)
8. برنامهٔ هفتهٔ اول و آموزش‌ها مشخص شد
9. سرپرست مستقیم و جانشین او مشخص شد

- برای هر تیک، **زمان و نام کسی که تیک زده** ذخیره می‌شود.
- می‌توانید مورد دلخواه اضافه کنید (تا ۲۴ مورد؛ بیشتر از آن چک‌لیست را غیرقابل استفاده می‌کند)
  و موارد اضافه را پاک کنید. حذف آخرین مورد رد می‌شود.
- **وضعیت دستی عوض نمی‌شود؛ از خودِ چک‌لیست می‌آید:**
  `برنامه‌ریزی‌شده` → با اولین تیک `در جریان` → با تیک همه `کامل شد`، و برداشتن یک تیک دوباره
  `در جریان`. یعنی «کامل شد» را نمی‌شود الکی زد.

## ۴. پیام خوش‌آمد

- دکمهٔ «ارسال پیام خوش‌آمد» متن را **از صندوق ایمیل خود سازمان** (تنظیمات › اتصال‌ها › ایمیل
  سازمان) می‌فرستد؛ از سرور دیگری نه.
- متن شامل نام کارجو، نقش، روز شروع، نام مسئول و چند مورد اول چک‌لیست است.
- اگر صندوق تنظیم نشده باشد: `409 EMAIL_NOT_CONFIGURED` و همان متن به‌صورت آمادهٔ کپی در صفحه
  نشان داده می‌شود. هیچ‌وقت «فرستاده شد» جعلی نمایش داده نمی‌شود.
- اگر کارجو ایمیل نداشته باشد: `409 NO_EMAIL` با همان راه‌حل (کپی متن).
- هر ارسال در تاریخچهٔ مکاتبات همان کارجو ثبت می‌شود (تنظیمات › اتصال‌ها › ایمیل‌ها) — ناموفق هم
  ثبت می‌شود، تا معلوم باشد چه چیزی نرسیده.
- سقف ارسال ساعتی فضای کاری رعایت می‌شود (`429 EMAIL_RATE_LIMITED`).
- ارسال دوباره ممکن است و عمداً بسته نشده: یادآوری روز اول یک نیاز واقعی است. هر ارسال یک
  کلیک جداگانه است؛ چیزی خودکار فرستاده نمی‌شود.

## ۵. خروجی برای منابع انسانی و حقوق

دکمهٔ **«خروجی اکسل»** یک فایل CSV می‌دهد (با BOM، پس اکسل فارسی را درست می‌خواند) با این
ستون‌ها:

`نام کارجو` · `ایمیل` · `نقش` · `دپارتمان` · `روز شروع (شمسی)` · `مسئول تحویل` · `وضعیت` ·
`پیشرفت` · `موارد باز`

برنامه‌های **لغوشده** در خروجی نمی‌آیند. همین داده از REST API هم خوانده می‌شود
(`GET /api/onboarding`)، پس اتصال به سیستم حقوق و دستمزد یک اسکریپت کوچک است، نه یک پروژه.

## ۶. مرزها (چیزهایی که این بخش عمداً نمی‌کند)

| موضوع | رفتار |
| --- | --- |
| **غربالگری بی‌طرف** | اگر روشن باشد، کل این صفحه با `409 BLIND_REVEAL_REQUIRED` بسته می‌شود؛ نام و ایمیل کارجو در هیچ پاسخی نمی‌آید. برنامه‌ای که قبل از روشن‌شدن ساخته شده هم پنهان می‌ماند. |
| **دسترسی هر آگهی** | برنامهٔ استخدام مربوط به یک آگهی محرمانه، برای عضو بیرون از فهرست مجاز دیده نمی‌شود (نه در فهرست، نه با شناسه، نه در شمارش‌ها). |
| **حذف رزومه (DSAR)** | با حذف دادهٔ کارجو، برنامهٔ تحویل و ایمیل‌هایش هم پاک می‌شوند و در شمارش حذف می‌آیند. |
| **حذف آگهی** | برنامه نمی‌رود؛ فقط اتصالش به آگهی باز می‌شود — آدم استخدام شده با حذف آگهی از کار بیرون نمی‌رود. |
| **حذف فضای کاری** | همهٔ برنامه‌ها پاک می‌شوند. |
| **کارهای خودکار** | هیچ ایمیل، پیام یا یادآوری‌ای بدون کلیک انسان فرستاده نمی‌شود. |

## ۷. API

| متد و مسیر | کار |
| --- | --- |
| `GET /api/onboarding` | فهرست + شمارش‌ها + وضعیت صندوق ایمیل |
| `GET /api/onboarding/hired` | کارجویان «استخدام‌شده» که برنامهٔ باز ندارند |
| `POST /api/onboarding` | ساخت برنامه `{ resumeId, startDateJalali?, ownerName?, note? }` |
| `PATCH /api/onboarding/:id` | تغییر تاریخ یا مسئول |
| `POST /api/onboarding/:id/tasks` | افزودن مورد `{ label }` |
| `POST /api/onboarding/:id/tasks/:taskId/toggle` | تیک/بازکردن |
| `DELETE /api/onboarding/:id/tasks/:taskId` | حذف مورد |
| `POST /api/onboarding/:id/welcome` | ارسال پیام خوش‌آمد از صندوق سازمان |
| `POST /api/onboarding/:id/cancel` | لغو برنامه (سابقه می‌ماند) |
| `DELETE /api/onboarding/:id` | پاک‌کردن کامل |
| `GET /api/onboarding/export` | CSV برای منابع انسانی/حقوق |

خطاها کد دارند تا رابط بتواند به‌جای متن عمومی، راه‌حل نشان دهد: `NOT_HIRED`، `PLAN_EXISTS`،
`BAD_START_DATE`، `TASK_TOO_SHORT`، `TOO_MANY_TASKS`، `LAST_TASK`، `NO_EMAIL`،
`EMAIL_NOT_CONFIGURED`، `EMAIL_FAILED`، `EMAIL_RATE_LIMITED`، `BLIND_REVEAL_REQUIRED`،
`NOT_FOUND`.

## ۸. آزمون

```bash
npm run test:onboarding      # ۷۶ بررسی
```

چه چیزی پوشش داده می‌شود: رد کردن برنامه برای کارجوی بررسی‌نشده، ساخت خودکار از پذیرش پیشنهاد با
همان روز شروعِ پیشنهاد، درستی تاریخ شمسی و شمارش روز، چرخهٔ کامل وضعیت، تیک با نام و زمان، افزودن و
حذف مورد، پیام خوش‌آمد بدون صندوق / با صندوق (روی SMTP ساختگی) و ثبت آن در مکاتبات، CSV با BOM و
بدون ردیف لغوشده، بسته‌شدن کامل در حالت بی‌طرف، جداسازی فضاهای کاری، و بقای داده پس از راه‌اندازی
دوبارهٔ سرور.
