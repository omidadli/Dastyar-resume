# انتقال به حقوق و دستمزد (HRIS)

> **چکیده:** استخدام با ما تمام می‌شود، پرداخت با سیستم حقوق. بند گم‌شدهٔ این دو، همان
> فایلی است که هر ماه یک نفر دستی بازتایپ می‌کند: نام، تاریخ شروع، حقوق، دپارتمان. هویدا این
> فایل را از دل همان داده‌ای می‌سازد که استخدام را ثبت کرده است، ستون‌هایش را به سلیقهٔ شما
> می‌چیند، و با یک کلیک — امضاشده — به سیستم حقوق می‌فرستد. هر چه نمی‌داند، خالی می‌گذارد.

مسیر: **منوی «حقوق و دستمزد»** (`/app/payroll`).

---

## ۱. فهرست از کجا می‌آید؟

منبع، **برنامهٔ تحویل پس از استخدام** است؛ همان که لحظهٔ پذیرش پیشنهاد خودکار ساخته می‌شود
([`ONBOARDING.md`](ONBOARDING.md)). یعنی:

```
پیشنهاد امضاشده  →  برنامهٔ تحویل  →  فهرست حقوق  →  فایل / ارسال
```

هیچ جدول دومی وجود ندارد که با جدول اول اختلاف پیدا کند. اگر تاریخ شروع را در برنامهٔ تحویل
عوض کنید، فایل حقوق همان روز عوض می‌شود. برنامه‌های «لغوشده» در فهرست نمی‌آیند.

| ستون پیش‌فرض | از کجا |
| --- | --- |
| کد پرسنلی | `H-0001`… — لحظهٔ ساخت برنامهٔ تحویل، یک‌بار و پایدار |
| نام و نام خانوادگی | نام کارجو در پرونده |
| ایمیل | ایمیل کارجو (اگر داده باشد) |
| عنوان شغلی / دپارتمان | از خود آگهی |
| تاریخ شروع (شمسی/میلادی) | از برنامهٔ تحویل |
| نوع همکاری / محل کار | از شرایط پیشنهاد؛ اگر نبود از آگهی |
| حقوق پایه / دورهٔ حقوق | **فقط** از پیشنهادِ پذیرفته‌شده |
| وضعیت تحویل / مسئول تحویل | از برنامهٔ تحویل |

## ۲. دو قاعدهٔ صادقانه

1. **حقوق حدس زده نمی‌شود.** اگر در پیشنهاد عددی نوشته نشده باشد (مثلاً «توافقی»)، سلول
   خالی می‌ماند و در بالای صفحه شمرده می‌شود: «بدون حقوق در پیشنهاد: ۳».
2. **دادهٔ خودِ حقوق را جمع نمی‌کنیم.** کد ملی، شمارهٔ بیمه، شمارهٔ حساب، وضعیت تأهل و پایهٔ
   سنوات در هویدا نیست و در فایل هم نمی‌آید؛ همان‌جا در سیستم حقوق تکمیل می‌شود.

## ۳. ستون‌ها مال شماست

دکمهٔ **«ستون‌های فایل»** فهرست ۱۵ فیلد را نشان می‌دهد؛ هر کدام را می‌توانید تغییر نام دهید یا
با خالی‌گذاشتنش از فایل حذف کنید. قواعد سرور:

| قاعده | پاسخ |
| --- | --- |
| دو ستون با یک نام | `400 MAPPING_DUPLICATE` |
| همهٔ ستون‌ها خالی | `400 MAPPING_EMPTY` |
| فیلد ناشناس | نادیده گرفته می‌شود (خطا نمی‌دهد) |
| ذخیره | روی فضای کاری می‌ماند و بعد از ری‌استارت هم هست |

## ۴. CSV: فایلی که اکسل درست باز می‌کند

`GET /api/hris/export.csv`

- **BOM یونیکد** در ابتدای فایل (بدون آن، اکسل ویندوز فارسی را «Ø­Ø§Ø­» نشان می‌دهد)
- پایان خط `CRLF`
- نقل‌قول هوشمند برای سلول‌های دارای `,` یا نقل‌قول
- نام فایل: `hovida-payroll-YYYY-MM-DD.csv`

## ۵. ارسال به سیستم حقوق (Webhook امضاشده)

`PUT /api/hris/endpoint` — نشانی دریافت‌کننده (فقط مدیر/مالک).

- نشانی باید `https` باشد؛ برای آزمایش روی سرور داخلی `127.0.0.1` پذیرفته می‌شود.
- کلید امضا: دست‌کم ۱۶ نویسه، یا خالی بگذارید تا ساخته شود. کلید **رمزنگاری‌شده** ذخیره می‌شود
  و دیگر هرگز برنمی‌گردد؛ فقط چهار نویسهٔ آخرش نمایش داده می‌شود.
- `POST /api/hris/push` — یک بار، با یک تلاش دوباره در خطای شبکه/۵xx:

```http
POST https://payroll.example.ir/hooks/hovida
Content-Type: application/json
X-Hovida-Event: hris.roster
X-Hovida-Delivery: hrp_…
X-Hovida-Signature: t=1760000000,v1=<hmac-sha256>
```

```json
{ "id": "hrp_…", "event": "hris.roster", "apiVersion": 1,
  "occurredAt": "2026-10-31T…", "org": { "name": "شرکت الف" },
  "columns": [{ "key": "employeeCode", "header": "کد پرسنلی" }],
  "mapping": { "employeeCode": "کد پرسنلی", "…": "…" },
  "currency": "IRT",
  "rows": [{ "employeeCode": "H-0001", "fullName": "نگار رضایی", "baseSalary": "61000000" }] }
```

امضا روی `${timestamp}.${body}` با همان کلید است — همان قاعده‌ای که در
[`API.md`](API.md) برای وب‌هوک‌ها آمده، تا یک کتابخانه در سمت شما هر دو را بسنجد.
سلول خالی به‌صورت رشتهٔ خالی (`""`) می‌آید، نه `null` و نه صفر.

## ۶. وقتی ارسال شکست می‌خورد

- نتیجه روی همان صفحه می‌ماند: «آخرین ارسال ناموفق — پاسخ ۵۰۰: …» با تاریخ شمسی و نام کسی
  که دکمه را زده است.
- در تاریخچهٔ فعالیت هم یک سطر ثبت می‌شود (`hris.push`).
- **هیچ‌وقت روی زمان‌بند نیست:** نه شبانه، نه با هر استخدام. فقط وقتی یک انسان دکمه را بزند.
- اگر دریافت‌کننده هنوز تنظیم نشده باشد: `409 HRIS_NOT_CONFIGURED` با همان جمله که کجا تنظیم
  می‌شود. فهرست خالی هم `409 ROSTER_EMPTY` می‌دهد (به‌جای فرستادن فایل خالی).

## ۷. دسترسی

| نقش | فهرست و CSV | ستون‌ها | تنظیم گیرنده | ارسال |
| --- | --- | --- | --- | --- |
| عضو تیم | ✅ | ❌ | ❌ | ❌ |
| مدیر / مالک | ✅ | ✅ | ✅ | ✅ |

در حالت **غربالگری بی‌طرف** کل این بخش بسته است (`409 BLIND_REVEAL_REQUIRED`): فهرست حقوق
نام و حقوق است، و آن حالت دقیقاً برای دیده‌نشدن هویت است.

## ۸. آزمون

```bash
npm run test:hris       # ۷۵ بررسی
```

پوشش: فهرست خالی و CSV آن (BOM، CRLF، سرستون فارسی)، ساخت برنامهٔ تحویل و رسیدن کد پرسنلی،
جداشدن نام/نام خانوادگی، خالی‌ماندن حقوق وقتی پیشنهاد عددی ندارد، رسیدن حقوق پس از امضا،
تغییر نام و حذف ستون، رد نام تکراری و فایل خالی، محدودیت نقش‌ها، رد http و کلید کوتاه،
تنظیم گیرنده روی سرور محلی، **بازبینی HMAC با همان کلید**، محتوای بدنه، ثبت موفقیت و شکست،
تلاش دوباره، جداسازی فضای کاری، بسته‌شدن در حالت بی‌طرف، و ماندگاری همه‌چیز (ستون‌ها، گیرنده،
لاگ ارسال) بعد از ری‌استارت — به‌همراه نبود کلید امضا و رمز SMTP به‌صورت متن در فایل ذخیره.

## ۹. آنچه هنوز نیست

- **آداپتور آمادهٔ سپیدار/هلو/کارپرداز** با فیلدهای اختصاصی هر کدام؛ فعلاً قرارداد JSON است و
  فایل CSV با هر ستونی که بخواهید. (فرمت دقیق هر سیستم، مستندِ خودش را می‌خواهد.)
- **همگام‌سازی دوطرفه** (خواندن تغییرات از سیستم حقوق). جهت امروز فقط خروجی است.
- **ارسال زمان‌بندی‌شده** (مثلاً اول هر ماه) — عمداً نیست؛ هر ارسال تصمیم انسان است.
