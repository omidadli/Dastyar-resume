# پرامپت آماده برای گرفتن و گذاشتن کلیدها (راهنمایی با Claude)

این فایل دو بخش دارد:

1. **پرامپت آماده** — متن داخل کادر را کامل کپی کنید، جاهای `{{...}}` را با اطلاعات خودتان پر کنید و برای Claude بفرستید.
   Claude قدم‌به‌قدم می‌گوید چه چیزی تهیه کنید، از کجا، و دقیقاً کجای هویدا بگذارید.
2. **جدول مرجع** — همان اطلاعات به‌صورت خلاصه، برای وقتی که خودتان می‌خواهید سریع کار را انجام دهید.

هیچ کلیدی را داخل چت (با Claude یا هر دستیار دیگری) نگذارید؛ دستیار فقط می‌گوید **چه** بگیرید و **کجا** بگذارید.

## ۱) پرامپت (کپی کنید)

```text
تو راهنمای فنی من برای راه‌اندازی یک نصب self-hosted از نرم‌افزار «هویدا» (سامانهٔ غربالگری رزومه و جذب) هستی.
هدف من: همهٔ قابلیت‌ها فعال شود و تنها کاری که بماند، گرفتن و وارد کردن کلیدهای لازم از داخل پنل مدیریت باشد.

وضعیت فعلی نصب من:
- آدرس سایت: {{https://hr.example.com}}
- روش اجرا: {{Docker / Node on a VPS / Cloudflare Worker + R2 / …}}، نسخهٔ {{1.0.0}}
- تعداد فضای کاری: {{۱}}، دامنهٔ ایمیل سازمان: {{example.com}}
- دسترسی من به سرور: {{دارم / ندارم}}   ← مهم: بعضی راه‌حل‌ها نیاز به دسترسی سرور دارند
- محدودیت سازمانی: {{مثلاً: مشتریان ایرانی؛ پرداخت بین‌المللی سخت است}} / {{محدودیتی ندارم}}

قابلیت‌هایی که باید فعال شوند:
۱) جست‌وجوی متخصص در LinkedIn با انتخاب دپارتمان + شرح آزاد («دنبال چه کسی با چه شرایطی هستم»)، و نتیجه فقط شامل
   افرادی که «Open to work» هستند، همراه با سابقهٔ کاری و خلاصهٔ پروفایل.
۲) ایمیل سازمانی: متن آماده در سایت با دکمهٔ «ارسال» از صندوق ایمیل خودِ سازمان برای کارجو برود.
۳) Google Calendar: با تعیین عنوان/تاریخ/ساعت/مدت/اطلاعات لازم و انتخاب کارجو، رویداد در تقویم ساخته و دعوت‌نامه
   برای کارجو ارسال شود.
(علاوه بر این، هوش مصنوعی برای تحلیل رزومه‌ها کلید می‌خواهد.)

در این نرم‌افزار، کلیدها دقیقاً این چهار جای مشخص وارد می‌شوند — راهنمایی‌ات باید به همین ساختار اشاره کند و از من
نخواهد فایل تنظیمات یا کد را تغییر دهم:
- «پنل مدیریت (/admin) ← اتصال‌ها ← جست‌وجوی متخصص در LinkedIn»: آدرس سرویس جست‌وجو (POST) + توکن Bearer.
  این مقدار یک‌بار برای کل نصب است و پیش از ذخیره با یک درخواست آزمایشی بررسی می‌شود.
- «پنل مدیریت (/admin) ← اتصال‌ها ← Google Calendar»: Client ID و Client Secret از یک OAuth Client نوع
  Web application، به‌همراه شناسهٔ تقویم (پیش‌فرض primary). نشانی بازگشتی که باید در Google Cloud ثبت شود
  در همان صفحه نوشته شده و شکلش این است: {{https://hr.example.com}}/api/integrations/calendar/callback
  دسترسی‌های موردنیاز: openid، email، https://www.googleapis.com/auth/calendar.events
- «پنل مدیریت (/admin) ← کلیدهای هوش مصنوعی»: یک یا چند کلید Google Gemini یا هر سرویس سازگار با OpenAI.
- «تنظیمات ← اتصال‌ها ← ایمیل سازمان» (داخل هر فضای کاری، نه پنل مدیریت): میزبان SMTP، پورت، TLS، نام کاربری، رمز،
  نام و نشانی فرستنده. اتصال پیش از ذخیره آزمون می‌شود.
- اتصال حساب گوگل هر فضای کاری، بعد از ثبت Client در پنل، از «تنظیمات ← اتصال‌ها ← اتصال حساب گوگل» انجام می‌شود.

از تو می‌خواهم این خروجی را بدهی:

الف) یک جدول «کلید/دسترسی ← از کجا تهیه کنم ← دقیقاً کجای هویدا وارد کنم ← چه کسی باید انجام دهد».
ب) برای هر مورد، گام‌به‌گام و به ترتیب اجرا (با لینک صفحهٔ رسمی سازنده)، شامل:
   - هوش مصنوعی: Gemini API Key یا کلید یک سرویس سازگار با OpenAI؛ سطح رایگان/پرداختی، سهمیه، و اگر پرداخت
     بین‌المللی ممکن نیست چه گزینه‌های قانونی دیگری هست.
   - جست‌وجوی LinkedIn: صریح بگو LinkedIn برای همه API جست‌وجوی افراد نمی‌فروشد؛ گزینه‌های مجاز را مقایسه کن
     (LinkedIn Talent Solutions / شریک رسمی، سرویس‌های دادهٔ دارای مجوز، یا سرویس داخلی خودشان که خودشان به
     منبع مجاز وصل است). برای هر گزینه بگو: چه چیزی تحویل می‌گیری (URL + توکن)، محدودیت نرخ، هزینهٔ تقریبی،
     و اینکه «Open to work» را واقعاً برمی‌گرداند یا نه. اگر گزینه‌ای در کشور من قابل خرید نیست، جايگزين بده.
     هیچ روش اسکرپ یا نقض شرایط استفاده پیشنهاد نکن.
   - Google Calendar: ساخت پروژه در Google Cloud، فعال‌کردن Calendar API، پیکربندی OAuth consent screen
     (Internal یا External + کاربران آزمایشی)، ساخت OAuth Client نوع Web application، ثبت دقیق redirect URI،
     و توضیح اینکه چرا همین URI و چرا بدون https یا با دامنهٔ متفاوت خطای redirect_uri_mismatch می‌دهد.
   - ایمیل سازمان: مقایسهٔ Gmail/Google Workspace (App Password و شرط فعال بودن تأیید دومرحله‌ای)،
     Microsoft 365 (SMTP AUTH)، Zoho و سرور SMTP داخلی؛ برای هر کدام میزبان/پورت/TLS را بگو و اینکه رمز
     واقعی حساب بهتر است یا رمز برنامه.
ج) یک چک‌لیست تیک‌خور برای بعد از وارد کردن هر کلید: دقیقاً چه کاری در سایت انجام دهم تا مطمئن شوم کار می‌کند
   (مثلاً «آزمایش و ذخیره» در کارت LinkedIn چه پیامی باید بدهد، «آزمایش اتصال» ایمیل، ساخت یک مصاحبهٔ آزمایشی،
   دیدن یک جست‌وجو با نتیجه) و پیام خطای رایج هر مرحله یعنی چه.
د) یک بخش «رفع اشکال» بر اساس پیام‌های واقعی:‎ ۴۰۱/۴۰۳ از سرویس جست‌وجو، ۴۲۹ سهمیه، invalid_client،
   redirect_uri_mismatch، 535 Authentication failed در SMTP، و «بررسی آنلاین ممکن نشد».
ه) یک جمع‌بندی «چه چیزی را هرگز در چت نفرستم» و روش امن انتقال کلید (مثلاً تایپ مستقیم در پنل،
   نه ارسال در پیام؛ در صورت اجبار، ساخت کلید موقت و چرخش آن).

قواعد پاسخ:
- فارسی، ساده و عملی؛ برای هر مرحله بگو «چه کاری، کجا، با چه مقداری، بعدش چه چیزی باید ببینی».
- فرض نکن من به کد یا فایل .env دسترسی دارم؛ مسیر همهٔ کلیدها از داخل خود سایت است. اگر جایی واقعاً
  به تنظیم سمت سرور نیاز بود، آن را جدا و صریح علامت بزن و بگو معادلش در پنل چیست.
- هیچ کلید واقعی از من نخواه و هیچ کلیدی را در متن مثال واقعی نگذار؛ فقط placeholder.
- اگر چیزی به کشور/تحریم/پرداخت بین‌المللی ربط دارد، محترمانه و بدون توصیهٔ دور زدن قوانین، جایگزین قانونی پیشنهاد کن.
- در پایان، ترتیب پیشنهادی انجام کارها را در ۵ خط خلاصه کن.
```

## ۲) جدول مرجع (خلاصهٔ همان پرامپت)

| چه چیزی | از کجا | کجای هویدا | سطح |
| --- | --- | --- | --- |
| کلید هوش مصنوعی (Gemini یا سازگار با OpenAI) | Google AI Studio / ارائه‌دهندهٔ سرویس | `/admin` › **کلیدهای هوش مصنوعی** | یک‌بار برای کل نصب (تا ۵ کلید با جابه‌جایی خودکار) |
| آدرس + توکن سرویس جست‌وجوی LinkedIn | LinkedIn Talent Solutions یا سرویس دادهٔ دارای مجوز | `/admin` › **اتصال‌ها** › جست‌وجوی متخصص در LinkedIn | یک‌بار برای کل نصب |
| Google Client ID / Secret | Google Cloud Console › OAuth client (Web application) | `/admin` › **اتصال‌ها** › Google Calendar | یک‌بار برای کل نصب |
| نشانی بازگشت گوگل | همان کارت، با دکمهٔ کپی | Google Cloud › Authorized redirect URIs | باید دقیقاً یکی باشد |
| SMTP سازمان (میزبان، پورت، کاربر، رمز، فرستنده) | مدیر ایمیل سازمان / پنل هاست | «تنظیمات ← اتصال‌ها ← ایمیل سازمان» | برای هر فضای کاری جدا |
| اتصال حساب گوگل | دکمهٔ «اتصال حساب گوگل» | «تنظیمات ← اتصال‌ها» | برای هر فضای کاری جدا |

> جمع‌بندی: تنها چیزی که «بیرون» از سایت لازم است، همان چهار قلم بالاست (هوش مصنوعی، سرویس جست‌وجو، OAuth گوگل،
> صندوق ایمیل). همهٔ آن‌ها از داخل خود سایت وارد می‌شوند؛ فایل تنظیمات سرور اختیاری است و فقط `APP_SECRET`
> (که اگر نگذارید خودکار ساخته می‌شود) برای رمزنگاری همان کلیدها استفاده می‌شود.
