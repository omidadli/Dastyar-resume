# ورود دومرحله‌ای (2FA)

> **چکیده:** هر عضو تیم می‌تواند روی حساب خودش، علاوه بر رمز عبور، یک کد ۶ رقمی از
> برنامهٔ احراز هویت گوشی (Google Authenticator، Microsoft Authenticator، Authy یا هر
> برنامهٔ TOTP) را لازم کند. بدون گوشی، هشت «کد بازیابی» یک‌بارمصرف راه ورود را باز
> نگه می‌دارد. هیچ سرویس بیرونی در مسیر نیست: کلید روی همان سرور ساخته و رمزنگاری
> می‌شود و کد QR هم همان‌جا رسم می‌شود تا کلید به هیچ واسطه‌ای نرسد.

---

## ۱. کجای محصول است؟

«تنظیمات › حساب کاربری › کارت **ورود دومرحله‌ای**» برای همهٔ نقش‌ها (مالک، مدیر، عضو)
باز است. شخصی است، نه سازمانی: هر کس فقط حساب خودش را روشن یا خاموش می‌کند.

## ۲. روشن‌کردن، در سه گام

1. **رمز عبور فعلی** را وارد و «راه‌اندازی» را بزنید. (بدون رمز، هیچ کلیدی ساخته نمی‌شود.)
2. برنامهٔ احراز هویت را باز کنید و **کد QR** را اسکن کنید؛ اگر دوربین نبود، «کلید دستی»
   را با دکمهٔ کپی بردارید و در برنامه «Enter a setup key» وارد کنید.
3. **هشت کد بازیابی** را همین‌جا بردارید (دکمهٔ «کپی همهٔ کدها») و بعد **کد ۶ رقمی**
   برنامه را وارد کنید. تا وقتی کدهای بازیابی را برنداشته‌اید، دکمهٔ روشن‌کردن فعال نمی‌شود.

از این لحظه، ورود دو مرحله دارد:

| گام | چه می‌فرستد | چه برمی‌گردد |
| --- | --- | --- |
| ۱ | ایمیل + رمز عبور | `{ twoFactorRequired: true, challenge, hint }` — **هیچ نشستی ساخته نمی‌شود** |
| ۲ | همان `challenge` + کد ۶ رقمی (یا یک کد بازیابی) | `{ token, user, org }` — نشست |

اگر رمز را دزدیده باشند، بدون کد هیچ کاری نمی‌توانند بکنند.

## ۳. قواعد امنیتی (همان‌هایی که پیاده شده است)

- **TOTP استاندارد:** HMAC-SHA1، ۳۰ ثانیه، ۶ رقم، ۱۶۰ بیت کلید تصادفی — دقیقاً همان
  چیزی که RFC 6238 می‌گوید و هر برنامه‌ای می‌خواند. یک پنجره (۳۰ ثانیه) اختلاف ساعت
  در هر جهت پذیرفته می‌شود.
- **هر کد یک‌بار:** شمارهٔ گامِ آخرین کدِ پذیرفته‌شده ذخیره می‌شود؛ همان ۶ رقم تا ۳۰
  ثانیهٔ بعد هم دوباره پذیرفته نمی‌شود (`CODE_REUSED`).
- **کد بازیابی یک‌بارمصرف:** فقط هش SHA-256 نگه داشته می‌شود؛ پس از استفاده، مصرف‌شده
  علامت می‌خورد و شمارندهٔ «کدهای باقی‌مانده» پایین می‌آید. ساخت مجموعهٔ تازه، مجموعهٔ
  قبلی را همان لحظه باطل می‌کند.
- **چالش یک‌بارمصرف و کوتاه:** ۵ دقیقه اعتبار، فقط برای همان حسابی که رمزش درست بوده،
  و پس از پنج کد اشتباه می‌میرد (`TOO_MANY_TRIES`).
- **محدودیت نرخ:** حداکثر ۱۰ کد اشتباه برای هر حساب در ۱۵ دقیقه. با فضای یک‌میلیونی
  کدها، حدس‌زدن عملاً بی‌فایده است.
- **کلید در پایگاه داده رمزنگاری‌شده است** (با همان کلید نصب که رمز SMTP را می‌پوشاند)
  و هرگز در پاسخ `/api/auth/me` یا در داده‌های ارسالی به مرورگر نمی‌آید؛ مرورگر فقط
  `twoFactorEnabled: true/false` را می‌بیند.
- **روشن‌کردن، دستگاه‌های دیگر را بیرون می‌کند:** بقیهٔ نشست‌های همان حساب بسته می‌شوند
  و باید با کد دوباره وارد شوند. نشستِ فعلی می‌ماند تا کاربر قفل نشود.
- **خاموش‌کردن، رمز + کد زندهٔ فعلی** می‌خواهد؛ کسی که فقط پشت یک نشست باز نشسته است
  نمی‌تواند آن را بردارد.
- **در نسخهٔ نمایشی روشن نمی‌شود:** رمز فضای نمایشی عمومی است و ۲FA آن‌جا فقط بازدیدکنندهٔ
  بعدی را بیرون می‌گذاشت. پیام صریح است، نه خطای مبهم.

## ۴. بازیابی وقتی گوشی نیست

1. در صفحهٔ ورود، سرِ گام دوم روی «به گوشی‌ام دسترسی ندارم» بزنید.
2. یکی از هشت کد `XXXX-XXXX` را وارد کنید (حروف بزرگ/کوچک و خط تیره اهمیتی ندارد).
3. وارد می‌شوید و شمارنده یک کم می‌شود. در «تنظیمات › حساب کاربری» با یک کد زندهٔ تازه،
   مجموعهٔ کدهای بازیابی را عوض کنید.

اگر هم گوشی و هم کدها رفته باشند، **مدیر فضای کاری** از «تنظیمات › تیم» دکمهٔ سپر کنار
نام عضو را می‌زند و «بازنشانی ورود دومرحله‌ای» را تأیید می‌کند: کلید و همهٔ نشست‌های آن عضو
برداشته می‌شود، با رمز عبور وارد می‌شود و می‌تواند دوباره روشنش کند. این کار در
فعالیت‌های تیم ثبت می‌شود (چه کسی، کِی).

قاعده‌های این بازنشانی، همان قاعده‌های مدیریت تیم است: عضو ساده نمی‌تواند کسی را
بازنشانی کند؛ مدیر نمی‌تواند کلید یک مدیر دیگر را بردارد؛ و کلید **مالک** فضای کاری از
داخل فضا برداشته نمی‌شود.

اگر خودِ مالک قفل شود، آخرین راه پنل سامانه است: `/admin` › کاربران › منوی هر کاربر ›
«برداشتن ورود دومرحله‌ای». هر دو مسیر در تاریخچه ثبت می‌شوند (مدیر سامانه در لاگ سکو،
مدیر فضای کاری در فعالیت‌های تیم). در فهرست تیم نشان سپر و در پنل سامانه برچسب «۲FA»
نشان می‌دهد چه کسی روشنش کرده است.

## ۵. API

همه زیر `/api/auth` (به‌جز بازنشانی مدیر که زیر `/api/org` است):

| مسیر | دسترسی | کار |
| --- | --- | --- |
| `POST /login` | عمومی | با ۲FA روشن: `{ twoFactorRequired, challenge, hint }` |
| `POST /2fa` | عمومی (با `challenge`) | کد یا کد بازیابی → نشست. خطاها: `401 INVALID_CODE`، `401 CODE_REUSED`، `401 INVALID_RECOVERY`، `401 CHALLENGE_EXPIRED`، `429 TOO_MANY_TRIES` |
| `GET /2fa` | نشست‌دار | `{ enabled, enabledAtISO, recoveryLeft, pending }` |
| `POST /2fa/setup` | نشست‌دار | `{ password }` → `{ secret, otpauth, qr, recoveryCodes }` (دوباره صدا زدن، ثبت ناتمام را با کلید تازه از نو می‌سازد) |
| `POST /2fa/enable` | نشست‌دار | `{ code }` → روشن می‌شود، بقیهٔ نشست‌ها بسته |
| `POST /2fa/disable` | نشست‌دار | `{ password, code }` → خاموش |
| `POST /2fa/recovery` | نشست‌دار | `{ code }` → هشت کد تازه، قبلی‌ها باطل |
| `POST /api/org/members/:id/2fa-reset` | مدیر/مالک | برداشتن ۲FA یک عضو + بستن نشست‌هایش (`403` برای مالک یا مدیر بالاتر، `409 NOT_ENABLED`) |
| `POST /api/admin/users/:id/reset-2fa` | مدیر سامانه | بازکردن قفل مالکی که گوشی و کدها را گم کرده؛ در لاگ سکو ثبت می‌شود |

## ۶. چه چیزی این نیست

- **SMS نیست.** پیامک در ایران هزینه و وابستگی اپراتور دارد و SIM-swap پذیر است؛ TOTP
  رایگان، آفلاین و امن‌تر است.
- **SSO/SAML نیست.** ورود سازمانی با دفاتر Google Workspace / Microsoft 365 هنوز در
  فهرست کارهاست (`docs/COMPETITORS.md`، جای خالی ۵).
- **اجباری نیست.** هیچ‌کس نمی‌تواند برای همکارش ۲FA را روشن کند؛ تصمیم خودش است. اگر
  مشتری سازمانی «الزام سازمانی» بخواهد، با یک سیاست سازمانی روی همان ستون اضافه می‌شود.

## ۷. تست

```bash
npm run test:2fa     # ۶۴ بررسی: ثبت‌نام تا خاموش‌کردن، بازنشانی مدیر و بازکردن قفل مالک از پنل سامانه
npm test             # شامل ۱۷ بررسی واحد TOTP و بردار رسمی RFC 6238
```

تست، کد را با یک پیاده‌سازی **مستقل** (crypto خالص) حساب می‌کند، نه با تابع سرور؛ پس اگر
سرور از استاندارد فاصله بگیرد، تست می‌شکند. همچنین بررسی می‌کند که کلید به‌صورت متن
ساده در فایل داده نباشد و کدهای بازیابی فقط هش باشند.
